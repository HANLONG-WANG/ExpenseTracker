# 余量：HTML → 安卓 UI 实现与验收对照

更新：2026-10-14。状态：UI已获用户认可；阶段A涉及的基础页面/控件已实施、对照并交付APK。UI01–UI27的完整业务仍按阶段B–E完成，此表是最终实现与验收依据。历史实施说明以阶段A最终审查为当前结论。

## 1. 基准与优先级

- 基准是已获认可的第55版实际渲染结果，以及本次冻结的源码包 [design-v55-source.tar.gz](reference/design-v55-source.tar.gz) 和 [逐文件校验值](reference/design-v55.sha256)。`?v=55` 只是缓存参数，不是不可变版本；后续对照应使用冻结包，不依赖随时可改的工作文件。
- 历史截图在 `design/previews/`；早期截图与第55版不一致时以冻结源码实际渲染为准。开发开始生成三主题×中日文的最新基准截图，包含滚动内容和交互状态。
- 业务依据为 [产品规格](product-design.md)、[落地规格](implementation-spec.md)；视觉依据为本文件与冻结 HTML。HTML 中假数据、示例算法、刷新重置、硬编码日期及 JS 叠加补丁不作为正式业务实现。
- `app.html` 按顺序加载 data → app → art → views → themes → forms → capture → experience → hierarchy → completion。最终页面可能被后续脚本重新定义，不能只读取 `views.js` 的初版。
- 安卓使用原生 Kotlin/Compose 实现，不能用正式 WebView 包装代替复刻。所有业务数据由本地库与正式计算生成。

## 2. 三主题迁移原则

| 主题 | 必须保留的独立表达 | 主要来源 |
| --- | --- | --- |
| 现代生活杂志 magazine | 编辑双栏、衬线正文、独立数字字体、期刊编号、边栏/细线、章节与编辑式菜单和日历 | `themes/magazine.css`、`themes.js`、`theme-system.css`、`experience.css`、`completion.css` |
| 纸质手账 journal | 手写字形、纸页/横线/旁注、盖章/勾选、手账导航、纸页弹窗、手写箭头与独立日历 | `themes/journal.css` 与对应公共文件中的 journal 分支 |
| 日常小物 objects | 圆体、钱袋/零钱盘/信封/行李箱、柔和立体层次、收纳标签、圆角菜单与小物日历 | `themes/objects.css`、`art.js` 与对应公共文件中的 objects 分支 |

共享的是 UiState、事件和计算；允许复用无样式结构、输入逻辑、绘图工具。三主题各自实现页面构图和组件外观，不通过一个通用 Material 页面仅替换颜色完成。

每套主题建立 display/body/number/meta 字体角色与颜色、间距、线宽、圆角、阴影、图表、动效参数；组件明确接收当前主题，弹层/键盘以上菜单也不能漏用主题。主题切换保留导航、表单、草稿和附件；语言/主题偏好按账本保存。

## 3. 字体、图形与测量

1. 从 `design/fonts/README.md` 和许可文件核对每个字形来源，保留许可与修改后的字体命名要求；导入安卓可用的 TTF/OTF，而不是将 WOFF2 文件直接放入 `res/font` 后假定可用。
2. 以浏览器实际使用的字体和文本边界为准测量。杂志金额 CSS 首选 Georgia，但浏览器可能已回退；核实实际字形与可分发权限。优先提取/转换已获许可的等价原字体，不未经许可打包系统 Georgia。无法一致时提供数字样张对照并记录具体差异，必要视觉微调不变成主题重设计。
3. 设计稿字体为文案子集。正式字体补齐固定中日文文案，并准备同体系较完整字库覆盖用户输入。分别检查中文、日文假名/汉字、拉丁、标点、币种、小数、负号；缺字时不能自动落入另一主题字体。
4. SVG 图标与 `art.js` 生成的插画提取为 Compose Path/ImageVector 或适当本地图片，保留 viewBox、路径、描边、颜色、层次、比例；不随意换成系统图标。记录需位图化的复杂图形及缩放质量。
5. 从最终 computed style/DOM 边界提取尺寸、间距、字距、行高、基线、旋转、装饰位置和 z-order。参考 fontScale=1 时 CSS px 与内容区 dp 对照，不直接拿设备物理像素当 dp。
6. 字体采用 Compose 字体资源与明确角色；自定义字形回退在安卓实际文本布局验证。[字体文档](https://developer.android.com/develop/ui/compose/text/fonts)

杂志数字的必要适配已具体对照：OFL Gelasio派生YohakuNumbers，仅校准行度量/名称，字形、字宽与字符映射未改；八组原稿/原生金额布局宽度偏差≤0.734dp、基线偏差≤1dp，局部字形墨迹差异明确保留。原字体、生成脚本、实际平台字体与前后样张见 [字体迁移记录](../android/verification/font-migration.md)。这是数值字体这一项的适配依据，不作为其他页面或全部字体已验收的结论。

## 6. 允许微调与验证

- 安卓真实状态栏、系统导航、IME、安全区域、权限弹窗、文件选择、外部打开按照系统能力工作；避免额外绘制假状态栏。[系统 Insets](https://developer.android.com/develop/ui/compose/system/insets)
- 标准fontScale=1与匹配内容宽度时，一比一对照应用内容区；保留字形、版式、颜色、间距、描边、图形、弹层、菜单、日期控件。大字体/窄屏/长用户内容允许必要换行、滚动或增加高度，不能通过缩小所有文字掩盖溢出。
- 可扩大不可见触控区域，保持视觉尺寸；减少动效尊重系统设置；软键盘弹出保证保存与关闭可达。
- 系统渲染引起的字形抗锯齿/阴影差异单独记录，不能把整页结构或字体改变归为“平台差异”。标准状态主要锚点偏移以1dp内为目标；超过或形成肉眼可见差异必须修正或记录有依据的微调，不通过调整截图尺寸掩盖。
- 每项微调记录页面、主题、原因、前后图和影响；常规系统适配直接处理，涉及已认可布局或交互变化先提供具体对照。
- 截图对照取相同语言、主题、内容区宽高、fontScale、数据和滚动位置；遮掉真实系统时间/光标等动态区域，保留应用区域。数字取自测试专用可信案例；差异图是定位手段，人工逐项检查字形、装饰与层次才是最终判定。
- 长页面分段截取；必须含未展开/展开菜单、日期左右字段切换、编辑/确认、媒体与空/失败状态。核心三主题×中日文完整检查，其余菜单使用组件基准与相关页面抽检，避免无意义的全组合爆炸。
