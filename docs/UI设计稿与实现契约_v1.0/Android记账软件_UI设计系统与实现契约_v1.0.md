**文档状态：可直接实现的基线契约**  
**视觉方向：静稳精确（Quiet Precision）**  
**冻结选择：1B、2A、3B、4B、5B、6B**  
**适用范围：Android 手机应用、Jetpack Compose 页面、MapLibre 地图、Vico 图表、Jetpack Glance 小组件**  
**设计系统唯一实现位置：`:core:designsystem`**

> 本文档已经精确到设计令牌、组件规格、页面结构、导航、状态、错误、无障碍、国际化、隐私和验收测试，可以直接作为开发实现依据。后续视觉图片评审若调整颜色、尺寸或排版比例，只允许通过设计令牌发布新版本；feature 页面不得自行改造形成局部风格。

# 1. 产品 UI 定位

## 1.1 核心风格

产品的视觉和交互目标定义为：

> **静稳、精确、可信、克制，并在长期高频使用中保持舒适。**

它不是银行后台，也不是卡通化、游戏化、奖励驱动的轻记账产品。界面应让用户感到数据可靠、操作可控、结构清楚，同时不要求用户理解借贷、科目或会计术语。

## 1.2 六项设计原则

1. **财务语义优先于装饰。** 金额、账户、日期、关系和状态必须先于插画、渐变或品牌表现。
2. **相同业务结构只出现一种组件。** 分类、金额、账户、状态、筛选、进度和警告不得在不同 feature 中重新设计。
3. **复杂信息通过渐进披露，不通过删减。** 高级字段折叠，但用户需要时必须完整可达。
4. **危险与日常严格分离。** 普通支出不使用错误红；红色只用于超支、逾期、数据错误和不可逆操作。
5. **离线和失败是正常状态。** 汇率、地图、Drive 或权限失败不能让核心记账界面失去可用性。
6. **颜色永远不是唯一信号。** 交易类型、预算状态、逾期和错误同时使用文字、图标、形状或位置。

## 1.3 明确禁止的视觉方向

- 禁止玻璃拟态、大面积透明模糊和难以验证对比度的背景。
- 禁止所有区块都做成悬浮大卡片。
- 禁止霓虹、黑金、博彩或交易所式视觉语言。
- 禁止大量高饱和分类色铺满整张卡片。
- 禁止庆祝彩纸、积分、连续打卡、夸张弹跳等游戏化动效。
- 禁止在 feature 内直接复制 Material 3 默认组件并局部改色。
- 禁止用红色表示所有支出。
- 禁止在用户界面出现“借方”“贷方”“会计科目”等底层术语。

# 2. 设计系统治理契约

## 2.1 唯一来源

所有视觉令牌和可复用组件必须位于 `:core:designsystem`。任何 feature 模块不得拥有自己的主题、颜色表、圆角表、阴影表、图标体系或同名组件副本。

设计系统公开六组基础对象：

```kotlin
LedgerTheme.colors
LedgerTheme.typography
LedgerTheme.spacing
LedgerTheme.shapes
LedgerTheme.motion
LedgerTheme.dimensions
```

机器可读值以 `android_ledger_ui_tokens_v1.json` 为准。Kotlin 源码由该文件生成或通过测试逐项校验，禁止人工维护两份不一致的值。

## 2.2 feature 模块允许与禁止

### feature 可以直接使用

- `Box`、`Row`、`Column`、`FlowRow`
- `LazyColumn`、`LazyRow`、`LazyVerticalGrid`
- `Canvas`
- `Modifier` 基础布局能力
- 使用 `LedgerTheme` 的 `Text`

### feature 必须通过设计系统包装使用

- Button、IconButton、FAB
- TextField、SearchField、SelectorField
- Card、ListItem、Chip、Badge
- Dialog、BottomSheet、Snackbar
- TopAppBar、NavigationBar、TabRow
- DatePicker、TimePicker
- ProgressIndicator
- 图表容器、地图覆盖层
- 空状态、错误状态、加载状态
- 敏感字段显示、身份验证入口

### feature 不得执行

- 写死十六进制颜色、ARGB 或自建 `ColorScheme`
- 写死通用间距、圆角、阴影和动画时长
- 在 feature 内创建 `MaterialTheme`
- 复制设计系统组件源码进行微调
- 混用不同图标家族
- 为同一语义发明不同状态色
- 对财务记录使用滑动删除

## 2.3 组件变体控制

每个组件只有本文定义的变体。需要新变体时，必须：

1. 证明现有变体无法表达需求；
2. 在 `:core:designsystem` 增加；
3. 更新 token、组件快照和无障碍测试；
4. 更新本文档版本；
5. 禁止先在 feature 中临时实现再长期保留。

## 2.4 版本规则

- 视觉令牌采用语义化版本：`major.minor.patch`。
- 破坏组件 API 或布局语义：major。
- 新增兼容组件或变体：minor。
- 只修正色值、间距、无障碍或渲染缺陷：patch。
- 页面必须依赖设计系统版本，不得读取未版本化的远端主题。

# 3. 视觉基础令牌

## 3.1 品牌色和表面色

品牌主色为深青绿色。浅色主题使用略带暖意的灰白表面；深色主题使用分级深灰，不使用全屏纯黑。

### 浅色主题核心值

|---|---:|---|
| `primary` | `#006B66` | 主按钮、当前导航、焦点、选中描边 |
| `onPrimary` | `#FFFFFF` | 主色上的文字和图标 |
| `primaryContainer` | `#A8F2E8` | 低强调选中背景、信息容器 |
| `onPrimaryContainer` | `#00201E` | 主色容器内容 |
| `background` | `#F7F8F5` | 应用背景 |
| `surface` | `#FCFDF9` | 主表面 |
| `surfaceContainer` | `#EEF1ED` | 分组容器、表单区 |
| `surfaceContainerHigh` | `#E8EBE7` | 强一级分组 |
| `onSurface` | `#191C1B` | 主文字 |
| `onSurfaceVariant` | `#414846` | 次级文字 |
| `outline` | `#707976` | 可交互边框 |
| `outlineVariant` | `#C0C9C6` | 分隔线、弱边框 |

### 深色主题核心值

| Token | 值 | 用途 |
|---|---:|---|
| `primary` | `#83D5CC` | 主按钮、焦点、选中 |
| `onPrimary` | `#003735` | 主色上的内容 |
| `primaryContainer` | `#00504C` | 低强调选中背景 |
| `background` | `#101413` | 应用背景 |

| `onSurfaceVariant` | `#C0C9C6` | 次级文字 |
| `outline` | `#8A9490` | 可交互边框 |
| `outlineVariant` | `#414846` | 分隔线、弱边框 |

完整值以 token JSON 为准。

## 3.2 语义颜色

| 语义 | 浅色基础色 | 深色基础色 | 使用场景 |
|---|---:|---:|---|
| 正向 `positive` | `#2E6B45` | `#8BD5A2` | 收入、完成、有效、余额增加 |
| 警告 `warning` | `#8A5B00` | `#F4C26B` | 临近超支、汇率过期、需要确认 |
| 危险 `danger` | `#B3261E` | `#FFB4AB` | 逾期、超支、校验失败、永久删除 |
| 信息 `info` | `#1D5F8A` | `#9DCCF5` | 退款、说明、外部服务状态 |
| 中性交易 | `#4D6070` | `#B9CAD8` | 转账、还款、贷款本金、余额调整 |

语义色和品牌色不得互相替代。例如品牌色不能表示“成功”，分类红色不能表示“错误”。

## 3.3 交易金额颜色

| 交易类型 | 金额颜色 | 必须同时显示 |
|---|---|---|
| 普通消费、费用 | `onSurface` | 减号或“支出/费用”文字、类型图标 |
| 收入 | `positive` | 加号、收入图标或文字 |
| 退款 | `info` | 加号、退款图标和“退款”标签 |
| 转账 | 中性交易色 | 双向箭头和“转账”文字 |
| 信用卡还款、贷款本金 | 中性交易色 | “还款/本金”文字，不得显示为费用 |
| 超支、逾期、错误 | `danger` | 警告图标和明确文字 |

禁止把全部支出染红。红色必须保留给真正异常或危险的状态。

## 3.4 分类色

- 系统提供 16 组分类前景色和容器色。
- 分类卡片主体使用中性表面；分类色只用于 44dp 图标容器、顶部小标记或 2dp 选中强调。
- 用户自定义颜色时，系统必须自动计算浅色和深色主题的前景色及容器色。
- 图标与容器对比度最低 3:1；分类名称与背景最低 4.5:1。
- 不合格颜色可以保存，但必须由系统自动替换前景色并显示对比度警告；不得让用户强制使用不可读文字色。
- 已删除分类使用中性灰图标、删除线名称和“已删除”文字，不继续显示高饱和分类色。

## 3.5 动态色

动态色默认可选，影响范围严格限制为：

- 主按钮、当前底部导航、焦点、选中背景；
- 顶栏和部分容器色调；
- 非财务语义的品牌装饰。

动态色不得改变：

- 收入、退款、警告、错误和逾期语义；
- 分类颜色；
- 图表序列色；
- 地图聚类和热力图色阶；
- 保险库危险操作色。

## 3.6 对比度

- 正文及金额：最低 4.5:1。
- 大于等于 18sp 或 14sp 粗体的大字：最低 3:1。
- 图标、边框和图形对象：最低 3:1。
- 焦点环与相邻背景：最低 3:1。
- 所有浅/深/动态色组合必须纳入自动对比度测试。

# 4. 字体和数字排版

## 4.1 字体

使用 Android 系统无衬线字体，不内置品牌字体。这样保证简体中文、日语和英语的字形、粗细、系统缩放和无障碍行为一致。

| 样式 | 字号/行高 | 字重 | 用途 |
|---|---:|---:|---|
| `amountHero` | 40/48sp | 600 | 账户余额、录入结果、核心指标 |
| `amountLarge` | 32/40sp | 600 | 详情页主要金额 |
| `amountMedium` | 22/28sp | 600 | 列表汇总、账单金额 |
| `titleLarge` | 24/32sp | 600 | 页面内容主标题 |
| `titleMedium` | 20/28sp | 600 | 区块标题、卡片重点 |
| `titleSmall` | 16/24sp | 600 | 行标题、表单分组标题 |
| `bodyLarge` | 16/24sp | 400 | 主要正文、输入值 |
| `bodyMedium` | 14/20sp | 400 | 次级正文、列表说明 |
| `bodySmall` | 12/16sp | 400 | 辅助说明、元数据 |
| `labelLarge` | 14/20sp | 600 | 按钮、重要标签 |
| `labelMedium` | 12/16sp | 600 | Chip、状态标签 |
| `labelSmall` | 11/16sp | 600 | 图例、短元数据 |

## 4.2 金额排版

- 金额必须启用 tabular figures（等宽数字特性）。
- 列表金额右对齐。
- 货币符号和数字不得拆行。
- 负号使用真正的减号 `−`，不是连字符 `-`。
- 正数在交易语义需要时使用 `+`；账户余额默认不加正号。
- 货币符号前后间距遵循地区格式；货币代码使用不换行空格，例如 `1,234.56 USD`。
- 零小数货币不得显示虚假 `.00`。
- 原币与账户币不同：账户币为主行，原币为次行；本位币估值只在详情或分析中显示。
- 超大金额不得缩写成 `1.2M` 作为唯一值；卡片可显示缩写，但点击或无障碍文本必须提供完整值。
- 隐藏金额显示等宽 `••••`，TalkBack 读作“金额已隐藏”，不得把实际金额写入语义树。

## 4.3 文本换行

- 页面标题最多两行；超过后完整标题通过 TalkBack 和详情可读。
- 列表主标题最多两行，次级信息最多一行；备注摘要最多一行。
- 表单标签不得省略号截断，必要时换行并增高字段。
- 200% 字体缩放时不得依赖固定高度；复杂横向行自动改为纵向布局。
- 不使用全大写英文标签。

# 5. 布局、密度、形状和动效

## 5.1 支持宽度

| 宽度 | 定义 | 主要规则 |
|---|---|---|
| 320–359dp | Compact | 12dp 横向边距；分类 3 列；扩展 FAB 改为图标 FAB |
| 360–479dp | Standard | 16dp 横向边距；分类 4 列；标准布局 |
| 480–599dp | Wide phone | 20dp 横向边距；分类 5 列；指标卡可两列 |
| ≥600dp | Large phone/foldable | 内容最大宽 720dp 并居中；表单最大宽 640dp；不创建独立平板信息架构 |

最低支持宽度为 320dp。应用只面向手机，因此不建立与手机不同的平板导航体系。

## 5.2 间距

基础间距序列：`2, 4, 8, 12, 16, 20, 24, 32, 40, 48, 64dp`。

- 页面横向标准边距：16dp。
- 紧凑宽度：12dp。
- 同一字段内部：4–8dp。
- 同组字段：12dp。
- 不同表单区：24dp。
- 页面大区块：32dp。
- 底部固定操作预留：至少 88dp。

不得自行使用 13dp、17dp、19dp 等无令牌值。

## 5.3 形状

| Token | 圆角 | 用途 |
|---|---:|---|
| `xs` | 4dp | 小色块、微型标记 |
| `sm` | 8dp | Chip、紧凑按钮、表格选中 |
| `md` | 12dp | 输入框、列表容器 |
| `lg` | 16dp | 主要卡片、分类卡片、底部面板 |
| `xl` | 20dp | 重点汇总卡 |
| `xxl` | 28dp | 模态底部面板顶部、FAB |
| `full` | 全圆 | 状态点、头像式图标容器 |

禁止每个 feature 自行选择不同圆角。

## 5.4 阴影与层级

界面主要通过色阶、描边和留白表达层级，阴影只用于：

- FAB：3dp；
- 模态底部面板：3dp；
- 临时悬浮菜单：3–6dp；
- 拖动中的卡片：6dp。

普通卡片默认 0dp 阴影，使用 `surfaceContainer` 和 1dp `outlineVariant`。

## 5.5 触控目标

- 所有可操作控件最小 48×48dp。
- 小图标视觉尺寸可以是 20–24dp，但命中区必须 48dp。
- 列表行最小 56dp；标准交易行 72–88dp。
- 分类卡片最小高度 92dp。
- 拖动把手必须有独立语义和 48dp 命中区。

## 5.6 动效

| 类型 | 时长 | 用途 |
|---|---:|---|
| Micro | 80ms | 按压、选中、图标切换 |
| Short | 140ms | Chip、折叠小区块 |
| Standard | 220ms | 页面内布局、底部面板 |
| Long | 320ms | 页面层级过渡、复杂图表范围变化 |

规则：

- 禁止弹簧式夸张回弹。
- 保存成功使用轻微淡出或勾选，不使用庆祝动画。
- 图表数据变化使用标准缓动，不从零反复播放。
- “减少动画”开启时，只保留不超过 80ms 的淡入淡出；位置和尺寸跳变直接完成。
- 加载骨架在 150ms 后才出现，避免短查询闪烁。

## 5.7 触觉反馈

- 分类选中、Chip 切换：轻触反馈。
- 拖动进入排序：一次长按反馈。
- 保存成功：轻确认反馈。
- 校验失败或危险操作被阻止：错误反馈。
- 连续输入和滚动不得反复震动。

# 6. 应用外壳、信息架构和导航

## 6.1 根结构

应用采用单 Activity、单 Compose 根树。根结构固定为：

```text
SessionGate
└── Ready
    └── RootScaffold
        ├── TopAppBar
        ├── CurrentTopLevelBackStack
        ├── BottomNavigation（5项）
        └── GlobalSnackbarHost / GlobalOperationBanner
```

`SessionGate` 必须先判断：`Uninitialized → Locked → OpeningBook → Maintenance / RecoveryRequired → Ready`。任何业务页面不得绕过锁定、维护或恢复拦截。

## 6.2 底部导航

底部固定五项，顺序和文案不可改变：

1. 记账
2. 流水
3. 账户
4. 预算
5. 分析

规则：

- 图标 24dp，标签始终显示。
- 高度 80dp，遵循系统导航栏 inset。
- 当前项使用品牌主色和轻量容器背景；非当前项使用 `onSurfaceVariant`。
- 每个顶层目的地保留独立 back stack。
- 点击其他项：恢复该项最近页面和滚动位置。
- 再次点击当前项：若不在根页则弹回根页；若已在根页则滚动到顶部。
- Android 返回键只回退当前栈；当前栈根页再返回时交由系统退出/后台处理，不自动切换到前一个 Tab。
- 模态流程、身份认证、系统文件选择器显示时隐藏底部导航。

## 6.3 顶栏

### 顶层页面

- 高度 56dp。
- 左侧显示当前顶层标题。
- 右侧最后一个操作固定为“更多功能”九宫格/菜单图标。
- 页面专属操作位于“更多功能”之前，例如搜索、隐藏金额、月份选择。
- 最多显示 3 个图标操作；其余进入溢出菜单。
- 不使用大标题折叠式 App Bar，以保持录入和数据页一致密度。

### 子页面

- 左侧为返回按钮。
- 中间标题最多两行。
- 右侧最多两个主操作，其他进入溢出。
- 表单保存不放在顶栏，统一使用固定 FAB 或底部操作栏。

## 6.4 “更多功能”入口

更多功能中心固定分组：

| 分组 | 入口 |
|---|---|
| 规划 | 项目、目标资金 |
| 负债 | 信用账户、分期、贷款 |
| 互请 | 互请活动 |
| 自动化 | 快捷模板、周期交易、候选记录 |
| 数据 | 导入、导出、备份、恢复、操作中心 |
| 基础数据 | 分类、商户、地点、实体卡、保险库 |
| 设置 | 外观、语言地区、币种、应用锁、隐私诊断、关于 |

该页面使用分组列表，不使用抽屉导航。具有待处理候选、失败备份、需补充结算或长任务时，入口右侧使用文字状态和 Badge，不只显示彩色圆点。

## 6.5 路由参数

导航参数只允许：

- 稳定 ID；
- 简单枚举；
- 年月、日期等非敏感值；
- 已保存筛选、报表或操作 ID。

禁止传递：

- 金额；
- 备注；
- 账户名称、商户名称或参与人名称；
- 卡号、安全码；
- 完整领域对象；
- 附件内容或文件路径；
- 备份密码。

路由完整定义见 `android_ledger_screen_contract_v1.yaml`。

## 6.6 深链接

允许的深链接目标仅限：

- 快速记账入口；
- 指定模板或分类的预填表单；
- 周期候选记录；
- 长任务状态；
- 小组件对应的账户、预算、信用卡或目标详情。

所有深链接先经过 SessionGate。应用锁开启时，认证完成后才恢复目标；敏感值不得出现在 URI。

## 6.7 页面恢复

- 冷启动默认进入“记账—支出”。
- 从后台短暂返回时默认恢复原页面；设置可改为始终恢复上次页面。
- 每个顶层栈保留滚动位置、当前月份、当前非敏感筛选 ID。
- 金额、备注、卡片信息、位置和密码不得写入 `SavedStateHandle`。
- 未保存表单只存在于 ViewModel 内存。进程被系统终止后，应用回到安全的来源页面，并显示一次性信息：“未保存的录入内容因应用被系统关闭而丢失。”不得创建隐式草稿。

## 6.8 边到边和系统栏

- 所有页面使用 edge-to-edge。
- 顶栏负责状态栏 inset，底部导航或固定操作负责导航栏 inset。
- 浅色主题状态栏图标使用深色；深色主题使用浅色。
- 地图可以延伸到系统栏下，但控件必须避开安全区。
- 保险库、全局禁止截屏页面设置 `FLAG_SECURE`；最近任务缩略图按隐私设置遮挡。

# 7. 全局 UI 状态契约

## 7.1 页面状态集合

每个 screen 的 `UiState` 必须显式表达下列适用状态，不能用 nullable 数据和多个布尔值隐式拼接：

```kotlin
sealed interface LoadState {
    data object Initial : LoadState
    data object Loading : LoadState
    data class Content(...) : LoadState
    data object Empty : LoadState
    data class Error(val code: UiErrorCode) : LoadState
}
```

业务页面按需要额外表达：

- `Refreshing`
- `Submitting`
- `ReadOnlyMaintenance`
- `PermissionDenied`
- `OfflineExternalService`
- `StaleValuation`
- `RevisionConflict`
- `Archived`
- `Trashed`
- `SensitiveLocked`

禁止以异常 message 直接渲染 UI。

## 7.2 加载

- 首次加载不足 150ms 不显示骨架。
- 列表骨架必须与真实行高度一致，最多显示 6 行。
- 不能用无限转圈替代已知进度。
- 加载时保留顶栏和导航，避免页面跳变。
- Paging 追加加载只在列表底部显示 48dp 行内进度，不遮挡已有内容。

## 7.3 空状态

空状态结构统一为：

1. 48dp 中性图标；
2. 一句明确标题；
3. 最多两句原因/下一步；
4. 一个主操作；
5. 可选一个次操作。

不得使用大面积卡通插画。首次安装无账户、无分类、无预算、无交易和无模板都必须有专门文案，不伪造示例数据。

## 7.4 错误状态

- 页面级错误使用 `LedgerErrorState`，含脱敏错误码、重试和可选帮助入口。
- 字段错误紧贴字段下方，使用 danger 色、错误图标和文字。
- 跨字段不变量错误同时显示顶部 `ValidationSummary`，点击错误可滚动并聚焦对应字段。
- 网络、地图、Drive 和汇率错误不得让本地数据页整体进入错误状态；使用局部 Banner。
- 数据库不可用、完整性失败或密钥失效才进入全屏故障状态。

## 7.5 警告与信息 Banner

| 级别 | 容器 | 图标 | 可关闭 |
|---|---|---|---|
| Info | info container | 信息 | 可选 |
| Warning | warning container | 警告 | 通常不可关闭，条件消失后自动消失 |
| Danger | danger container | 错误/危险 | 不可关闭，必须处理 |
| Neutral | surfaceContainerHigh | 中性说明 | 可关闭 |

Banner 文字必须说明原因和后果，不能只写“出现问题”。

## 7.6 Snackbar

Snackbar 只用于短暂、可恢复、非关键结果：

- 保存成功；
- 已移入回收站；
- 已清除不兼容卡片；
- 已复制卡号并将在指定时间清空剪贴板；
- 已保存筛选。

关键错误、密码错误、永久删除和恢复失败不能只用 Snackbar。普通 Snackbar 4 秒；带操作 8 秒；TalkBack 开启时遵循系统建议延长。

## 7.7 只读维护态

维护、迁移或恢复验证期间：

- 当前可见数据可继续读取时显示只读 Banner；
- 所有写入按钮禁用并提供原因；
- 不允许表单进入可编辑状态；
- 预计可取消的操作显示取消；不可取消阶段明确写“正在完成安全提交，请勿关闭应用”。

## 7.8 冲突态

交易、预算或其他有版本控制的实体保存时发生 `expectedRevision` 冲突：

- 不得静默覆盖；
- 显示“数据已在其他操作中改变”；
- 提供“重新加载”“查看差异”“取消”；
- 不提供默认强制覆盖；
- 用户重新应用修改后产生新的正式修订。

# 8. 核心组件契约

## 8.1 `LedgerScaffold`

**用途：** 所有普通全屏页面统一外壳。  
**组成：** 顶栏、内容、可选底部导航、SnackbarHost、可选固定 FAB、可选全局 Banner。  
**规则：**

- 自动处理系统 inset；
- 内容最大宽度 720dp，表单最大宽度 640dp；
- 固定操作不得遮住最后一项，内容自动增加底部 padding；
- 不允许 feature 自行创建第二个 SnackbarHost。

## 8.2 `LedgerTopAppBar`

变体只有：`TopLevel`、`Back`、`Selection`、`ModalClose`。

- 高度 56dp；
- 图标按钮 48dp；
- `Selection` 显示已选数量和“全选当前结果”的状态；
- 禁止 feature 自定义顶栏高度或背景渐变。

## 8.3 `LedgerNavigationBar`

- 固定五项；
- 标签始终显示；
- 当前项图标可使用填充版，非当前使用轮廓版，但必须属于同一图标家族；
- Badge 包含语义文本，例如 TalkBack 读作“候选记录，3 项待处理”。

## 8.4 `LedgerSaveFab`

- Standard 宽度且键盘隐藏：扩展 FAB，图标＋“保存”。
- Compact 或键盘显示：56dp 图标 FAB。
- 固定在内容右下；与底部导航和 IME 保持 16dp 间距。
- 表单无效时仍可点击，点击后执行验证并滚动到首个错误；只有提交中、维护中或权限前置条件绝对缺失时禁用。
- 提交中用 20dp 进度替换图标，保留“正在保存”语义。

## 8.5 `LedgerButton`

变体：`Primary`、`Secondary`、`Tonal`、`Text`、`Danger`。

- 高度 48dp，紧凑工具栏可 40dp；
- 主要流程每个视图最多一个 Primary；
- Danger 只用于不可逆或高风险操作；
- 禁止只用颜色区分危险按钮，必须有明确文案。

## 8.6 `LedgerIconButton`

- 视觉图标 24dp；命中区 48dp；
- 无可见标签时必须有 `contentDescription`；
- 溢出菜单统一使用三个垂直点；
- 删除图标不得直接执行永久删除。

## 8.7 `AmountText`

参数至少包含：

```kotlin
data class MoneyUiModel(
    val formatted: String,
    val fullAccessibleText: String,
    val semantic: AmountSemantic,
    val visibility: AmountVisibility,
    val secondaryFormatted: String? = null
)
```

规则：

- 只接受已格式化 UI model，不在 Composable 内做 BigDecimal 或汇率计算；
- 支持 `Hero`、`Large`、`Medium`、`List` 四种尺寸；
- `visibility = Hidden` 时语义树不得包含真实值；
- 交易语义色由 `AmountSemantic` 映射，feature 不传任意颜色。

## 8.8 `MoneyStack`

用于多币种显示：

- 第一行：账户币种权威金额；
- 第二行：原币金额，仅在不同币种时显示；
- 第三行：本位币历史估值，只在详情、分析或用户展开时显示；
- 汇率和报价时间放在关联说明，不塞入金额行。

## 8.9 `MetricCard`

- 手机上标准为一列或两列；
- 重点金额使用 `amountMedium` 或 `amountLarge`；
- 标题、值、比较值和简短说明顺序固定；
- 可点击时显示明确箭头和语义；
- 不可使用随机渐变背景；
- 同一页面最多一个 `Emphasized` 变体。

## 8.10 `StatusBadge`

变体：`Neutral`、`Positive`、`Info`、`Warning`、`Danger`、`Candidate`、`Archived`、`Deleted`。

- 高度 24–28dp；
- 必须包含短文字，不能只显示圆点；
- `Deleted` 使用灰色和删除线关联名称；
- `Candidate` 使用轮廓和“未入账”文字。

## 8.11 `CategoryGrid`

- Compact 3 列、Standard 4 列、Wide 5 列；
- 水平/垂直间距 8dp；
- 支持一级分组、二级卡片、搜索结果和创建入口；
- 一级分类即使有子分类也必须可直接选择；
- 选择交易分类和分类重新选择必须使用同一组件和同一交互。

### `CategoryTile`

- 最小高度 92dp；
- 图标容器 44dp；
- 卡片使用中性表面，分类色集中在图标容器；
- 名称最多两行；
- 一级分类增加小型“一级”文字或层级标记，不通过不同组件表达；
- 选中态：2dp primary 描边＋淡 primary overlay＋右上角勾选；
- 禁止整卡高饱和彩色背景。

## 8.12 `JournalTransactionRow`

标准结构：

```text
[40dp 分类图标] [分类/交易类型 + 商户或备注]
                [账户 · 卡片 · 状态标识]
                                      [账户币金额]
                                      [必要时原币]
```

- 高度 72–88dp，按内容自然增长；
- 右侧金额固定右对齐；
- 项目、互请、退款、分期、附件和来源标识按优先级显示，最多 4 个可见，更多合并为“另有 N 项”；
- 全局流水不显示运行余额；账户流水增加独立运行余额列或下一行；
- 不能滑动删除；长按进入选择模式；点击进入详情。

## 8.13 `AccountSummaryCard`

- 显示账户图标、名称、类型、币种余额；
- 外币账户显示本位币估值和汇率时间；
- 有目标资金时显示实际余额、预留和可用余额；
- 信用账户显示负债、可用额度和最近到期状态；
- 归档账户降低强调并显示“已归档”，不把余额隐藏。

## 8.14 `ProgressSummary`

用于预算、项目、目标、额度、分期和贷款：

- 进度条高度 8dp；
- 进度必须同时显示已用/总额或已完成百分比；
- 超过 100% 后进度条保持满格，额外显示超出金额和 danger 文案；
- 负结转、负可用余额不能用反向进度条，改用单独警告行；
- TalkBack 读出完整数值，不只读百分比。

## 8.15 `LedgerTextField`

- 最小高度 56dp；
- 圆角 12dp；
- 标签始终可见或在聚焦后浮动；
- 错误文字位于字段下方；
- 必填通过“必填”文字或错误表达，不只用星号；
- 禁止把可选择实体伪装成可自由输入的下拉框。

## 8.16 `MoneyExpressionField`

组成：

1. 币种和金额表达式输入；
2. 实时规范化表达式；
3. 计算结果；
4. 可选操作符工具栏；
5. 舍入或汇率说明；
6. 错误位置提示。

规则：

- 使用系统键盘，不提供数字键盘；
- 工具栏只有 `+ − × ÷ ( )` 和删除/移动光标所需的最小操作；
- 全角、半角和本地小数分隔符自动规范化；
- 错误必须指明位置，例如“第 5 个字符附近缺少右括号”；
- 计算结果大于零才能保存；
- 原始表达式和最终结果同时显示，但最终结果视觉优先。

## 8.17 `SelectorField`

用于账户、卡片、商户、项目、目标、活动等实体选择。

- 不是下拉菜单；
- 小集合（≤8 且无搜索需求）可以用底部面板；
- 大集合、可创建、可搜索或多选必须进入全屏选择页；
- 选中值显示图标、名称和必要状态；
- 归档实体在历史编辑中可见但默认不可用于新交易；
- 清空操作必须有明确“无”选项。

## 8.18 `DateTimeZoneField`

- 默认一行显示本地日期和时间；
- 时区与账本默认一致时放在辅助文本，不重复占据主行；
- 时区不同或跨日时必须显式显示；
- 日期和时间分别可编辑；
- 信用账单归属时区与交易发生时区不得混为同一个字段。

## 8.19 `FormSection`

- 使用标题、可选说明、内容和可选尾部操作；
- 普通区块不使用悬浮卡片，依靠留白和分隔；
- 高级区块可以折叠；
- 必填核心字段不得放入折叠区；
- 折叠状态可在页面生命周期内保留，但不得跨不同交易错误复用。

## 8.20 `ValidationSummary`

- 表单提交后出现在首个错误之前或顶部；
- 显示错误数量和可点击错误列表；
- 点击后滚动、展开所在折叠区并聚焦字段；
- 屏幕阅读器优先获得错误摘要。

## 8.21 `SearchField`

- 高度 52dp；
- 搜索图标、输入、清除、可选筛选入口；
- 输入 150–250ms 防抖，但本地 FTS 可根据性能调整；
- 不把自由文本搜索历史发送或写入未加密存储；
- 搜索结果必须保留当前筛选摘要。

## 8.22 `FilterBuilder`

- 每个维度独立区块；
- 同维度多选显示“任一”，跨维度摘要显示“同时满足”；
- 已选条件用可删除 Chip；
- 底部固定“重置”和“应用”；
- 应用前显示预计结果数可以异步，但不得阻塞编辑；
- 位置半径使用地图选择器；
- 保存方案和设为默认是应用后的二级操作。

## 8.23 `AttachmentField`

- 显示缩略图或文件类型图标、显示名称、大小和状态；
- 大文件导入显示确定进度；
- 允许安全取消；
- 图片点击内部预览，其他文件点击先显示外部打开提示；
- 不显示应用私有物理文件名和哈希。

## 8.24 `LocationField`

状态文案固定为：

- “正在获取位置…”
- “已获取 · 精度约 X 米”
- “未获得位置，可正常保存”
- “位置权限未授予”
- “已手动调整”

保存时如仍定位中，FAB 进入最多 3 秒的“等待位置”状态；超时自动保存无位置，不弹阻塞错误，不在后台补写。

## 8.25 `ChartCard`

- 标题、范围/口径、图表、图例、摘要、查看数据表；
- 最小高度 220dp，推荐 280dp；
- 坐标网格弱化；
- 当前系列突出，其余降噪；
- 触摸 marker 显示完整日期和精确值；
- 必须提供文字摘要和可访问数据表；
- 图表颜色只来自 chart tokens。

## 8.26 `AccessibleDataTable`

- 图表下方可展开；
- 第一行/列有语义表头；
- 大数据使用分页或虚拟列表；
- 金额保持等宽、右对齐；
- 导出和复制遵循敏感字段规则。

## 8.27 `MapPanel`

- MapLibre MapView 通过统一 AndroidView 包装；
- 统一控件：模式、权重、筛选、定位、缩放、attribution；
- 聚类使用品牌青绿；热力图使用顺序青绿色阶，不用红绿风险色；
- 地图加载失败时保留列表/汇总替代，不显示空白黑块；
- 底部详情面板圆角 20dp，最多覆盖屏幕 55%，可展开全屏。

## 8.28 `OperationProgressPanel`

显示：

- 操作名称；
- 当前阶段；
- 当前/总量或百分比；
- 已处理数量、必要时估计剩余但不做虚假精确时间；
- 取消/暂停能力；
- “可安全取消”或“正在安全提交，不可取消”说明；
- 失败后的重试、查看错误、清理临时文件状态。

不得只显示无限进度条处理十万行导入或数十 GB 备份。

## 8.29 `SensitiveValueField`

- 默认掩码；
- 每次显示完整卡号、复制完整卡号、显示安全码分别触发认证；
- 安全码没有复制按钮；
- 右侧显示剩余可见秒数；
- 30 秒、页面离开、应用后台或锁定立即清除；
- TalkBack 在掩码态不得读取隐藏值；
- 截屏和录屏始终禁止。

## 8.30 `HighRiskConfirmation`

适用于永久清除、替换恢复、清除本机数据、删除云端备份和重加密历史备份。

- 明确列出范围、不可逆后果和不受影响的内容；
- 高风险操作要求输入固定确认短语；
- 涉及云端备份或保险库时再次认证；
- 主操作使用 Danger，取消使用 Primary/Secondary；
- 禁止默认焦点落在危险按钮。

# 9. 交互和表单行为契约

## 9.1 保存和校验

1. 用户点击保存；
2. 页面先执行 UI 格式校验；
3. 若有错误，展开相关区块并聚焦首个错误；
4. 格式校验通过后调用 application command；
5. 保存期间防止重复提交，FAB 显示进度；
6. 领域错误映射为本地化错误码；
7. 成功后执行规定导航，不进行乐观假成功；
8. 失败时保留用户输入，不清空表单。

必填字段在用户离开字段后可以显示错误；跨字段规则在提交或相关字段都填写后显示。首次打开空表单不应立即出现一屏红色错误。

## 9.2 返回和未保存更改

- 没有修改：直接返回。
- 有修改：显示“放弃未保存更改？”对话框，操作为“继续编辑”“放弃”。
- 不提供“保存草稿”，因为正式需求明确没有草稿状态。
- 系统文件选择器、身份验证或子选择页返回，不视为放弃表单。
- 切换底部导航时，有未保存表单必须先确认；不得在后台隐式保存。

## 9.3 键盘和焦点

- 金额字段默认请求焦点仅在从模板/分类进入编辑器且用户尚未填写金额时；编辑已有交易不自动弹键盘。
- IME `Next` 按视觉顺序移动；最后字段使用 `Done` 收起键盘，不直接保存。
- 固定 FAB 必须跟随 IME 上移。
- 搜索页打开时自动聚焦搜索框；从搜索结果返回时恢复查询和位置。
- 大字体下横向字段改为纵向后，焦点顺序仍按视觉从上到下。

## 9.4 选择器策略

| 场景 | 组件 |
|---|---|
| 2–8 个固定单选、无需搜索 | 底部面板或分段按钮 |
| 可能超过 8 个、需要搜索 | 全屏选择页 |
| 可创建实体 | 全屏选择页，底部固定“新建” |
| 多选 | 全屏选择页，固定应用栏 |
| 分类 | 始终完整分类网格 |
| 日期/时间 | Material 3 日期/时间选择器包装 |
| 时区、币种 | 全屏可搜索列表 |
| 图表类型 | 底部图形选项网格 |

不得使用 HTML 式下拉列表或在一行中塞入过多选项。

## 9.5 手势

- 点击：打开详情或选择。
- 长按交易行：进入多选。
- 长按并拖动：仅用于分类、模板、参与人、仪表板卡片等明确排序场景。
- 横向滑动：只用于月份分页、Tab 内容和图表范围，不用于删除。
- 双击、隐藏长按菜单或复杂手势不得成为唯一操作入口。

## 9.6 删除和撤销

### 移入回收站

- 使用普通确认对话框；有依赖时先进入影响范围页。
- 成功后 Snackbar 可提供“撤销”。撤销的领域含义是恢复并产生新修订，不是回滚数据库历史。

### 永久清除

- 只在回收站且领域验证允许时显示。
- 使用 HighRiskConfirmation。
- 显示历史、附件、依赖和合并恢复影响。
- 不提供 Snackbar 撤销。

## 9.7 权限

- 只在用户触发相关功能时请求。
- 请求前用本地解释页面说明用途、是否阻塞和替代方案。
- 位置权限拒绝后仍可记账。
- 通知权限拒绝后长任务仍可在允许范围内执行，但明确系统限制。
- SAF 或 Drive 授权失效使用局部修复入口，不把整个应用锁死。

## 9.8 网络

- 核心页面不显示全局“离线模式”横幅，除非当前功能依赖网络。
- 汇率离线显示缓存来源和报价时间。
- 地图离线/不可用显示无底图替代面板或列表。
- Drive 离线保留本地备份状态并允许稍后重试。
- 重试必须有界；UI 不显示无休止旋转。

## 9.9 刷新

- 本地数据库 Flow 自动更新，不使用手动下拉刷新作为主要同步机制。
- 需要外部数据的页面可以提供“更新汇率”“重新加载地图”“刷新 Drive 列表”。
- 下拉刷新只能刷新当前外部数据，不应重跑全部分析或重建投影。

## 9.10 选择模式和批量操作

- 顶栏切换为 Selection 变体，显示已选数量。
- 支持选择可见项、全选当前筛选结果和清除选择。
- “全选当前筛选结果”使用查询选择语义，不把所有 ID 加载到内存。
- 筛选改变后必须提示选择范围已变化并重新确认。
- 批量写入前显示将修改字段和记录数；默认原子提交。

# 10. 数据格式化与文案契约

## 10.1 货币

- 权威格式由 `CurrencyFormatter` 统一生成。
- 货币小数位来自币种元数据，不使用统一两位。
- 千位分隔、十进制分隔和符号位置默认跟随系统地区，可由应用地区设置覆盖。
- 无法唯一识别符号时显示代码，例如 `10.00 USD`，避免 `$` 歧义。
- JPY 示例：`¥1,200`；USD 示例：`$12.34` 或 `12.34 USD`。
- 负数：`−¥1,200`；正向交易：`+¥1,200`。
- 分析和表格允许括号表示负值的导出格式，但应用 UI 统一使用减号。

## 10.2 汇率

显示格式固定为：

```text
1 USD = 152.0000 JPY
来源：缓存 · 报价 2026-07-30 16:00 · 获取 2026-07-31 08:12
```

- 根据精度去除不必要尾零，但至少保留能解释账户金额的精度。
- 人工覆盖显示“手动”；不得伪装成在线报价。
- 过期缓存使用 Warning，仍允许保存。

## 10.3 日期和时间

- 列表日期分组使用本地化短日期，如“7月31日 周五”。
- 同年详情可省略年份，跨年必须显示年份。
- 交易详情同时提供本地发生时间和时区；不同于默认时区时显示 UTC offset。
- 创建/修改审计时间使用账本设置地区格式，但不改变存储时区。
- 月份选择统一使用 `YYYY年M月` / locale equivalent。

## 10.4 百分比、利率和权重

- 百分比按场景保留 0–2 位小数。
- 年利率明确标注“年利率”或“实际年化利率”，不得只显示 `%`。
- 互请权重显示相对数，例如 `2 : 1 : 1`，不伪装成百分比。
- 预算执行率超过 100% 时显示 `125% · 超出 ¥...`。

## 10.5 交易类型文案

内部枚举不得直接展示。用户文案固定为：

| 内部类型 | 用户主文案 |
|---|---|
| EXPENSE | 支出 |
| INCOME | 收入 |
| TRANSFER | 转账 |
| REFUND | 退款 |
| CREDIT_PAYMENT | 信用卡还款 |
| LOAN_DISBURSEMENT | 贷款放款 |
| LOAN_PAYMENT | 贷款还款 |
| BALANCE_ADJUSTMENT | 余额调整 |
| FX_EXCHANGE | 外币兑换 |
| SETTLEMENT_PAYMENT | 互请结算 |
| OPENING_BALANCE | 期初余额 |

贷款还款组件必须分别标为“本金”“利息”“手续费”“罚息”。

## 10.6 统计口径文案

- `isConsumption = true`：生活消费。
- `EXPENSE + !isConsumption`：非消费费用。
- 信用卡还款、贷款本金、转账：不计入费用。
- 退款：费用冲减，不称为收入。
- 余额调整、期初余额：不计入收入、费用、消费或预算。
- 互请：只显示“本人承担部分”计入消费和预算。

## 10.7 自动生成文案

任何自动信用卡还款、贷款还款或周期交易必须使用：

- “已自动生成记账记录”；或
- “已生成待确认候选”。

禁止使用“银行已扣款”“还款已成功”“支付已完成”等现实支付断言。

## 10.8 错误文案

错误必须包含：发生了什么、是否保存、下一步是什么。例如：

- 正确：“未保存。退款金额超过剩余可退金额 ¥800。请减少金额，或在高级选项中明确允许超额退款。”
- 错误：“操作失败。”

原始异常、SQL、路径、密钥、堆栈和第三方响应正文不得显示。

- 状态必须有文字，不只显示数字圆点。

# 12. 分功能页面与流程契约

## 12.1 首次启动 `ONB-001`—`ONB-010`

首次启动使用同一 `OnboardingScaffold`：顶部显示步骤 `n/10` 和可返回箭头，内容区滚动，底部固定“继续”。可选步骤显示“稍后设置”，不可用灰色按钮代替跳过。

| 步骤 | 页面 | 必须内容 | 关键规则 |
|---:|---|---|---|
| 1 | 语言 | 简体中文、日语、英语 | 选择立即更新后续页面语言 |
| 2 | 本位币 | 可搜索法定货币，默认 JPY | 首次正式交易后不可直接修改的说明 |
| 3 | 默认时区 | 当前系统时区和时间预览 | 默认 `Asia/Tokyo` 只在系统匹配时预选 |
| 4 | 隐私政策 | 可滚动完整文本、必要同意 | 未同意不能继续；不得预勾选 |
| 5 | 功能统计与崩溃 | 两个独立开关、白名单摘要 | 首次确认前不得发送；开关可分别关闭 |
| 6 | 应用锁 | 设备能力、超时、跳过 | 默认关闭；无设备安全锁时说明限制 |
| 7 | 恢复密码与备份 | 不可找回警告、备份位置、跳过 | 密码不得写入 SavedState；支持稍后设置 |
| 8 | 第一个账户 | 内嵌简化账户创建、跳过 | 不自动创建账户或示例余额 |
| 9 | 第一个分类 | 方向、名称、图标、颜色、跳过 | 不自动生成默认分类 |
| 10 | 完成 | 已设置摘要、进入应用 | 进入空白账本，不导入示例数据 |

返回前一步必须保留已确认的非敏感设置。恢复密码输入离开页面后不保留明文；若流程重建，要求重新输入。

## 12.2 记账首页和分类

### 12.2.1 分类层级

每个一级分类形成一个 `CategoryGroupSection`：

- 组标题为一级分类名称和图标；
- 一级本身作为首个可选卡片，带“一级”标记；
- 二级分类随后按排序显示；
- 组可以折叠，但首次进入默认展开；
- 搜索结果使用同一 `CategoryTile`，副标题显示父分类；
- 分类为空时显示创建入口，不建议默认分类。

### 12.2.2 快捷模板

- 有模板时显示一行最近/固定模板，最多 5 个加“全部”。
- 模板卡片显示图标、名称和可选金额；不得显示为一键入账。
- 点击模板进入完整交易编辑器，并显示“来自快捷模板”中性说明。

### 12.2.3 其他交易

六个卡片顺序固定：

1. 内部转账
2. 信用卡还款
3. 退款
4. 贷款操作
5. 余额调整
6. 外币兑换

卡片包含图标、标题和一句用途说明。不得加入互请活动管理；互请只在支出表单内关联，管理入口在更多功能。

## 12.3 普通支出和收入编辑器

### 12.3.1 页面模型

```kotlin
data class TransactionEditorUiState(
    val mode: EditorMode,
    val transactionId: StableId?,
    val revisionId: StableId?,
    val direction: ExpenseOrIncome,
    val category: CategoryUiModel?,
    val amount: MoneyExpressionUiState,
    val account: AccountUiModel?,
    val card: CardUiModel?,
    val merchant: MerchantUiModel?,
    val occurredAt: ZonedDateTimeUiModel,
    val project: ProjectUiModel?,
    val settlement: SettlementEditorUiState,
    val location: LocationUiState,
    val note: String,
    val attachments: ImmutableList<AttachmentUiModel>,
    val semantics: TransactionSemanticsUiState,
    val validation: ValidationUiState,
    val submit: SubmitUiState
)
```

UiState 不得包含 Room Entity、Posting 或 Journal 对象。

### 12.3.2 默认值可解释性

系统按需求中的优先级选择默认值。UI 对自动选择的账户/卡片可以显示一行轻量来源，例如“来自分类默认”或“最近使用”，但不强制显示在所有情况下。用户手动改动后来源说明消失，后续字段不得覆盖用户选择。

账户改变后：

- 兼容卡片保留；
- 不兼容卡片自动清空；
- Snackbar 明确说明；
- 不自动选择另一张卡，除非用户尚未手动选择且分类默认有兼容卡。

### 12.3.3 高级统计与预算

折叠区按交易方向显示：

- 支出：生活消费/非消费费用；计入月度预算；可选信用账单归属；项目月度预算快照说明。
- 收入：常规收入/非经常性收入。
- 默认值显示“使用分类默认”；用户覆盖后显示“本笔覆盖”。
- 历史编辑必须展示原修订快照，不因当前分类默认变化而自动改变。

### 12.3.4 位置

进入手工录入页面后可开始一次前台定位。用户可：

- 查看和移动地图点；
- 关联已有地点；
- 删除本次位置；
- 在权限拒绝或超时后继续保存。

页面不得自动填入商户或地点，只能显示“建议”。

### 12.3.5 保存后行为

- 新建支出/收入：回到相同 Tab 和原分类网格滚动位置，Snackbar“已保存”。
- 编辑交易：回到交易详情，详情刷新到新修订。
- 从候选进入：回到候选列表并标记已生成交易。
- 从批量行编辑进入：返回批量表格，不提交主账本。

## 12.4 互请分配区

互请开关开启后依次显示：

1. 活动；
2. 实际付款人；
3. 参与人；
4. 分配模式：平均、指定金额、百分比、权重；
5. 税费和服务费分配；
6. 舍入规则；
7. 汇总：总金额、本人承担、他人承担、头寸变化。

规则：

- 一笔交易只允许一个实际付款人。
- `paid` 和 `owed` 不平衡时，顶部显示差额并禁用最终提交。
- 结算币种与交易币种不同，必须显示换算证据和最终结算币金额。
- 外部参与人付款时，本地账户字段隐藏或明确“不影响本地账户”。
- 普通用户文案使用“应收/应付”“对方欠你/你欠对方”，不使用内部账户术语。

## 12.5 其他交易专用表单

### 12.5.1 内部转账 `REC-013`

字段顺序：转出账户、转入账户、转出金额、转入金额/汇率（不同币种）、时间、备注、附件。

- 相同账户不得保存。
- 相同币种时只输入一个金额。
- 不同币种时账户金额均为权威证据；有效汇率自动计算并可与在线/缓存报价比较。
- 显示“不计入收入、费用或预算”。

### 12.5.2 信用卡还款 `REC-014`

字段：付款银行账户、信用账户、金额、还款分配、时间、备注。

- 默认分配到最早未结清账单；
- 允许选择具体账单或未分配；
- 主动超额还款阻止保存；
- 被动正余额只在详情和账户状态中表达；
- 页面固定显示“此记录表示软件记账，不证明银行扣款成功”。

### 12.5.3 退款 `REC-015`

模式：关联原交易、独立退款。

关联模式显示：

- 原交易摘要；
- 原金额、累计已退、剩余可退；
- 本次退款金额；
- 收款账户/卡；
- 继承的分类、商户、项目、互请和目标；
- 费用归属日期；
- 预算恢复策略；
- 项目和目标恢复策略；
- 高级超额覆盖。

超额覆盖必须在 danger 容器中说明，并要求再次确认；不得作为普通开关与其他字段同级。

### 12.5.4 贷款放款和还款

贷款放款显示合同、分项、收款账户和金额分配。贷款还款使用组件表格：本金、利息、手续费、罚息，各项合计必须等于支付总额。本金超过剩余本金时阻止保存；未来计划只作为建议，不自动改变实际金额。

### 12.5.5 余额调整

- 显示“不会计入收入、费用、消费或预算”。
- 可关联余额检查点。
- 方向使用“增加余额/减少余额”，不使用借贷。

### 12.5.6 外币兑换

同时显示转出金额、转入金额、有效汇率、参考汇率、汇兑成本/价差和舍入。价差只有按领域规则形成费用时才进入费用说明。

## 12.6 批量录入

### 12.6.1 摘要表格

手机端使用可横向滚动的受控表格，固定第一列行号和最后一列错误状态。默认显示：分类、金额、账户/卡、商户、日期、项目。复杂字段以图标/摘要表示，点击行进入完整编辑器。

操作：

- 新增、复制、删除未提交行；
- 批量粘贴；
- 排序；
- 校验；
- 提交整批；
- 放弃整批。

### 12.6.2 校验

- 每行显示错误数；
- 顶部汇总按错误类型分组；
- 点击错误跳到行和字段；
- 任一错误默认阻止整批提交；
- 警告允许用户确认后继续；
- 提交阶段显示原子性说明和持久化进度。

## 12.7 流水、搜索和筛选

### 12.7.1 列表结构

- 默认倒序并按发生地本地日期分组。
- 日期头可以显示当日收入/费用摘要，但不得增加查询阻塞；不可用时只显示日期。
- Paging 初始页建议 30–50 行，具体由性能测试确定。
- 使用 keyset Paging，UI 不提供跳到“第 N 页”。

### 12.7.2 搜索

全文搜索覆盖分类、商户、备注、项目、互请活动、参与人和附件显示名称。搜索栏下方显示当前范围，例如“本月 · 全部账户 · 不含回收站”。不得搜索保险库字段、银行账号或附件内容。

### 12.7.3 筛选

筛选页包含：日期范围、交易类型、账户、卡片、分类、商户、项目、互请活动/参与人、币种、金额、位置/半径、附件、退款、分期、来源、预算属性、消费性质、回收站、创建/修改时间。

- 同维度选项使用 OR；
- 不同维度使用 AND；
- 顶部生成自然语言摘要；
- 支持保存名称、复制、设为默认和删除；
- 默认筛选方案在流水首页以首个 Chip 显示。

### 12.7.4 批量编辑

仅提供需求允许字段：分类、账户/卡、商户、项目、时间、备注、预算属性和统计性质。金额、账务方向、退款关系和互请份额不得出现在 UI。

## 12.8 交易详情和历史

交易详情从上到下：

1. 主要金额、分类/类型、发生时间；
2. 状态和来源标签；
3. 用户录入内容；
4. 账户影响；
5. 预算、消费/费用性质；
6. 多币种和汇率；
7. 退款、账单、分期、贷款、周期、项目、目标、互请关系；
8. 位置；
9. 附件；
10. 创建/修改信息；
11. 历史预览；
12. 编辑、退款、复制为模板、移入回收站等操作。

### 账户影响

使用自然语言，例如：

```text
现金钱包  减少 ¥1,250
餐饮费用  增加 ¥1,250（折叠的技术解释，不显示科目）
```

默认只显示用户账户变化和经济影响，不显示内部系统账户。数据完整性页面可以在“技术详情”中展示平衡检查结果，但仍不要求用户理解借贷。

### 历史

时间线显示：创建、编辑、批量编辑、移入回收站、恢复、依赖重写。每项显示时间、来源和字段变化摘要。版本对比按区块列出旧值/新值；未变化字段默认折叠。恢复旧版按钮文案为“以此版本创建新修订”。

## 12.9 回收站和依赖处理

- 回收站顶部显示保留期和预计自动清理规则。
- 行显示删除时间、自动清理日期和依赖数量。
- 恢复先运行依赖校验。
- 永久清除不可用时显示原因，例如“仍有退款依赖”“未到保留期限”“正在被备份操作读取”。
- 多项永久清除使用操作中心显示验证和清理进度。

## 12.10 账户首页与账户详情

### 12.10.1 账户首页

- 顶部核心指标名称严格受控。
- 账户按现金/银行、信用、贷款分组。
- 同币种显示账户金额；外币增加本位币估值。
- 汇率不可用时显示原币余额和“暂无当前估值”，不得显示 0。
- 无账户时主操作“创建账户”，次操作“导入数据”。

### 12.10.2 创建账户

流程：选择类型 → 基本信息/币种 → 类型专属设置 → 可选期初余额 → 完成。

- 现金/银行：名称、机构/分行/账号可选、币种、显示样式。
- 信用：随后进入账单日、还款日、时区、额度等信用设置。
- 贷款：转入贷款合同向导，而不是用普通账户表单塞入全部条款。
- 期初余额明确不计入收入或预算。

### 12.10.3 账户详情

内容：余额、可用余额、估值、趋势、快捷操作、实体卡、目标资金、检查点、近期流水。信用和贷款账户使用相同外壳，但主内容由负债模块扩展。

账户流水必须显示每笔交易后运行余额。运行余额与交易金额分成两个右对齐列；Compact 宽度下运行余额放在金额下方。

### 12.10.4 余额检查点

用户输入日期和现实余额后显示：账面余额、现实余额、差额。提供“查看附近流水”“创建余额调整”“仅保存检查点”。检查点本身不改变余额。

## 12.11 实体卡和保险库入口

实体卡详情只显示非敏感信息：名称、尾号、所属账户、状态、更换关系和历史交易。保险库入口明显独立，进入后必须认证。卡片归档不影响历史显示；更换操作创建新卡并链接旧卡，不覆盖尾号。

## 12.12 预算

### 12.12.1 月份导航

预算顶层页使用月份分页和明确上一月/下一月操作。未来月份可进入并编辑，历史月份显示“历史月份”标签。月份改变时保留垂直滚动到顶部，避免不同月份错位对比。

### 12.12.2 汇总区

必须分别显示：

- 基础总预算；
- 历史结转，可正可负；
- 本月调整；
- 可用总额；
- 已用金额；
- 剩余/超出；
- 尚未发生周期固定支出；
- 今日可用金额。

不得把基础预算、结转和调整合并成一个无法解释的总数。

### 12.12.3 分类预算

层级行显示：图标、分类名、已用/可用、进度和超出金额。一级行可以展开二级；无预算分类仍显示消费及“未单独设置预算”。父级真实消费包含子级，界面需显示“已包含子分类”，避免用户误解为重复计算。

### 12.12.4 编辑和约束

编辑器实时显示：

- 一级预算合计 / 总预算；
- 每个一级下二级合计 / 一级预算；
- 剩余未分配金额；
- 超限差额。

超限行使用 danger 文案并阻止保存。结转不参与基础预算约束，必须在独立区显示。

### 12.12.5 调整

调整类型：清除结转、增加/减少可用额、分类间转移、归档分类结转转移。页面顶部固定显示“此操作不改变账户余额，也不会创建财务交易”。历史调整不可直接编辑；修改通过反向/新调整由领域决定，UI 显示版本。

### 12.12.6 历史重算

修改历史交易或历史预算导致后续结转链重算时：

- 当前页面显示 Recalculation Banner；
- 受影响月份标注“正在重算”；
- 结果完成后自动刷新；
- 重算失败进入操作中心并禁止展示旧版本缓存为当前结果。

## 12.13 项目

### 列表

项目卡显示名称、日期范围、预算使用、状态、关联目标和需补充结算标识。支持活动/归档 Tab。空状态提供新建项目。

### 详情

固定 Tab：概览、交易、现金流。概览包含预算、本人实际承担费用、月度预算包含策略、目标、互请活动和关键日期。交易页使用流水组件并预设项目筛选。现金流页区分费用、收入和净现金流。

### 编辑

字段：名称、说明、开始/结束、项目预算、本项目是否计入月度预算、一个目标。改变“计入月度预算”只影响新交易；页面必须说明历史交易快照不会自动重算。

### 归档和重新开放

归档后默认不能用于新交易。需要临时使用时，项目详情提供“重新开放”；不得在交易选择器中悄悄选择归档项目。

## 12.14 目标资金

### 列表

按账户分组，每个目标显示进度、目标金额、截止日期、当前预留和账户可用余额。账户目标总预留超过实际余额时，分组顶部显示 Warning，但不自动调整任何目标。

### 详情

内容：目标进度、实际账户余额、目标预留、账户可用余额、建议月存、历史曲线、绑定项目和资金操作历史。

### 资金操作

- 分配：增加目标预留；
- 释放：减少预留；
- 调整：显式修正；
- 交易支出和退款的目标变化在交易详情中展示。

实际余额不足时只警告，不阻止保存。目标完成后显示三个选项：释放、保留、继续使用。

## 12.15 负债总览

负债管理页分信用账户、分期和贷款三部分，显示：当前信用负债、贷款剩余本金、未来分期承诺和最近到期/计划。到期状态属于信息展示，不扩展为提醒系统。

## 12.16 信用账户和账单

### 12.16.1 信用账户详情

顶部显示：

- 当前总负债；
- 本期剩余应还；
- 未出账金额；
- 已还金额；
- 可用额度；
- 临时额度及到期；
- 最近账单和还款日；
- 逾期状态。

信用卡出现正余额时显示“溢缴/退款形成的正余额”，不显示负债为负数而不解释。

### 12.16.2 账单列表

每期账单显示周期、到期日、预计/官方状态、应还、已还、剩余和未还/部分/已还清/逾期状态。列表不显示最低还款额。

### 12.16.3 账单详情

官方金额与预计金额并列，差异单独显示。官方金额录入后不得自动创建余额调整。封存账单使用“已封存”Badge；编辑其中交易前显示影响警告。

### 12.16.4 账单归属

交易详情和编辑器允许选择前一期、自动当前期或后一期。选择器显示周期、状态和金额影响。手动归属有“手动”标签并进入交易修订。

### 12.16.5 自动还款记账

设置页显示资格清单：官方账单、剩余应还、默认银行账户、账户状态、重复检查。条件不足时正式模式不可选或自动降级候选，并说明具体原因。页面始终显示现实支付免责声明。

## 12.17 信用卡分期

### 创建/编辑

字段：关联购买、信用账户、本金、期数、费用模型、费率/固定费、首期费、实际年化、提前结清规则、退款重算策略和舍入。保存前必须生成计划预览。

### 详情

显示已出账负债、未出账承诺、剩余本金、已付费用、未来费用、进度、关联购买和退款影响。购买消费已在原交易确认，页面不得按每期重复显示为新消费。

### 计划

期次表格列：期号、账单日期、本金、利息、手续费、剩余本金。最后一期舍入尾差显示说明。

### 提前结清

输入日期和规则后显示本金、费用、提前结清手续费、节省成本和新旧计划差异。计算结果不影响真实账本，只有明确“应用并记录”后才进入后续流程。

## 12.18 贷款

### 12.18.1 合同向导

贷款向导分六步：

1. 基本信息与币种；
2. 一个或多个贷款分项；
3. 每个分项条款；
4. 利率阶段；
5. 计划预览；
6. 检查并创建。

组合贷款通过多个分项卡片展示，每个分项有名称、本金、利率和计划摘要。步骤间允许返回，所有敏感输入只在内存。

### 12.18.2 条款编辑

支持固定/浮动利率、等额本息、等额本金、先息后本、一次性、自定义计划，支付频率、提前还款策略、缩短期限/降低月供、违约金和舍入规则。表单根据选择渐进展开，不显示无关字段。

### 12.18.3 利率阶段

时间线显示生效日期、结束日期、年利率、基准和加点。重叠立即标红并说明冲突区间。新增阶段后必须重新生成未来计划预览，旧计划作为历史版本保留。

### 12.18.4 贷款详情

顶部显示剩余本金、已还本金、已付利息/费用、进度、下一计划、计划与实际差异。Tab：概览、计划、交易、利率、模拟。组合贷款概览先显示总计，再列分项。

### 12.18.5 实际还款

表单按本金、利息、手续费、罚息分配，并可关联计划期次。合计必须等于账户支付金额；本金不能超过剩余本金。保存后交易详情显示账户现金流和非消费费用影响。

### 12.18.6 提前还款模拟

模拟参数、策略和结果全部使用中性色容器并标记“模拟，不影响账本”。结果至少比较：未来总支付、利息/费用、期数、月供、结束日期。应用模拟需二次确认，并明确将创建新条款/计划版本及相关实际交易。

## 12.19 互请活动

### 列表和详情

活动列表显示总体应收/应付、参与人、项目、状态和补充结算标识。详情顶部用自然语言：“你应收 ¥…”或“你应付 ¥…”。参与人行显示已付、应承担、已结算和净额。

### 记录结算

选择付款人、收款人、金额和日期。self 参与时显示本地账户并创建正式交易；self 不参与时隐藏本地账户，显示“不影响你的本地账户”。允许多次部分结算。

### 补充结算

已完成活动中的原交易修改后，详情不改写历史结算，而显示“需要补充结算”。页面列出历史已结算、当前理论头寸和差额，可记录新结算。

### UI 派生决策：建议转账

为使净额结算可操作，UI 可以展示由 application/domain 查询服务返回的最少或近似最少转账建议。该建议仅为显示和预填，不改变领域不变量；用户仍可记录任意合法部分结算。若后端未实现建议算法，页面保留净额列表和手动记录，不得在 UI 端自行计算并写账。

## 12.20 快捷模板和周期交易

### 快捷模板

模板编辑复用交易表单组件，但隐藏实际时间、实时位置、附件和实时汇率。允许金额为空。模板列表支持搜索、排序、归档；使用模板必须进入完整录入页。

### 周期规则

规则编辑器按频率动态展示：工作日、每周/若干周、多星期几、月固定日、月末、第几个星期几、若干月、每年、自定义间隔、起止、次数、时区、周末调整和缺失日策略。下方实时显示未来 10 次发生日期，便于验证。

### 生成模式

- 正式生成：明确“系统将创建记账记录，但不代表现实支付发生”；
- 候选：明确“候选不影响余额、预算或报表”。

### 修改范围

修改系列发生项时使用底部面板：仅本次、本次及以后、整个系列。不得用含糊的“保存修改”。

### 候选记录

候选列表使用轮廓 Badge“未入账”。打开候选后进入完整交易编辑器，操作为“确认并记账”“跳过”“取消”。确认失败保留候选和输入。

## 12.21 分析系统

### 12.21.1 固定报表目录

必须提供以下 20 项入口：

1. 收入、费用与净结余
2. 现金流
3. 消费分类结构
4. 分类趋势
5. 商户排行与趋势
6. 账户余额和核心净金融资产
7. 汇兑重估
8. 月度和分类预算执行
9. 项目预算和现金流
10. 消费地图
11. 信用卡负债、账单和额度使用
12. 分期余额和手续费
13. 贷款本金、利息、进度和未来计划
14. 目标资金
15. 周期支出和订阅
16. 退款和费用冲减
17. 互请活动与结算
18. 多币种消费和汇兑成本
19. 多维交叉分析
20. 数据完整性报告

目录按“收支、资产负债、规划、关系、数据质量”分组，不按数据库模块分组。

### 12.21.2 报表通用结构

- 顶部：标题、时间范围、筛选摘要、口径帮助、导出；
- 指标摘要；
- 主图表；
- 比较/趋势；
- 数据表；
- 可下钻明细。

报表加载时显示已知范围，不清空整个页面。查询失败显示可重试错误，不展示过期缓存为当前结果。

### 12.21.3 图表选择

- 折线：时间趋势；
- 柱状：类别比较；
- 堆积：构成随时间变化；
- 饼图：最多 6 个有限类别，超出自动改条形图并合并“其他”；
- 表格：精确值和多维结果；
- 地图：地点维度；
- 进度：预算和目标。

图表类型不兼容时，UI 显示原因并建议可用类型。

### 12.21.4 自定义报表

手机端使用步骤式构建：指标 → 维度 → 筛选 → 时间粒度/比较 → 排序 → 可视化 → 预览保存。禁止用户输入 SQL 或数学公式。定义可保存、复制和加入仪表板。

### 12.21.5 自定义仪表板

手机上以单列可重排卡片为主，指标卡可以两列。拖动时有把手和辅助菜单“上移/下移”，确保 TalkBack 可排序。卡片编辑进入报表构建器，不在仪表板内放复杂弹出菜单。

### 12.21.6 异常和预测

每项显示：结论、影响值、比较基准、算法名称/版本、时间窗口和阈值。不得使用“AI发现”“智能洞察”等文案。

## 12.22 消费地图

- 默认当月消费；
- 顶部模式：消费、全部费用、现金流、全部有位置交易；
- 权重：金额、笔数；
- 汇总：商户、地点；
- 表现：聚类、热力图；
- 默认隐藏转账、还款和贷款；
- 使用历史交易汇率折算金额。

地图点点击后显示底部面板：名称/坐标、总金额、笔数、分类构成和交易预览。放大后可显示单笔交易。地图失败时提供同样数据的地点列表替代。

## 12.23 分类、商户和地点管理

### 分类

管理页使用树列表而非录入网格，以支持排序和状态操作；分类选择仍使用网格。二级分类的父级创建后只读。删除流程显示历史引用数量，并提供重分配、归档、墓碑删除。修改统计性质时说明只影响新交易，另提供批量重算入口但必须走独立高风险流程。

### 商户

列表支持搜索、别名和合并。合并页同时选择来源和目标，显示将影响的当前交易和地点数量；历史修订仍可追溯，不在 UI 声称旧实体消失。

### 地点

地点编辑使用地图点和可选商户。合并/拆分页显示位置记录分布，用户选择记录归属；不得在线反向解析地址。

## 12.24 附件

图片在应用内安全预览，支持缩放但不得生成长期明文缓存。其他格式显示元数据后，外部打开前弹出提示：文件将通过一次性授权提供给其他应用，其他应用的隐私行为不受本应用控制。重命名只修改显示名称。

## 12.25 导入

通用 CSV/Excel 导入采用九阶段向导：

1. 文件和模式；
2. 工作表、编码、表头；
3. 字段映射；
4. 实体映射与创建缺失实体；
5. 币种和汇率；
6. 校验和疑似重复；
7. 预览和提交摘要；
8. 影子库/主库提交进度；
9. 结果和按批次撤销。

规则：

- 解析和预览阶段明确“尚未写入账本”；
- 错误按行和字段定位；
- 十万行不使用普通 Compose Table 一次性渲染，使用分页/虚拟列表；
- 提交前列出将创建的账户、分类、商户等实体；
- 默认整批全有或全无；
- 取消后显示临时文件清理状态；
- 导入记录可按批次撤销，但每笔交易仍有独立历史。

结构化工作簿增加实体类型选择和引用完整性检查。附件只通过专用压缩包或完整备份迁移。

## 12.26 导出

流程：内容 → 格式 → 字段 → 位置 → 进度/结果。

- 当前筛选 CSV 自动带入流水筛选摘要；
- 全量 Excel 显示将生成的工作表；
- 位置坐标是单独敏感开关，默认关闭；
- 完整卡号、安全码永远不出现在字段列表；
- 覆盖同名文件前确认；
- 成功后提供“打开”“分享”“查看位置”。

## 12.27 备份

### 首页

显示最近成功备份、最近失败、下次策略、位置、保留数量、恢复密码状态和保险库包含策略。不要使用“已同步”。

### 恢复密码

必须说明：本应用和服务器均无法找回。密码强度只依据长度和规则，不上传。更改密码时提供“只影响未来备份”或“重新加密可访问历史备份”，后者进入长任务。

### 备份历史

每个快照显示日期、逻辑内容、物理增量大小、位置、验证状态和是否包含保险库。损坏或未验证使用明确状态。

### 手动备份

提交前显示范围、位置、是否包含保险库和预计空间信息。备份过程中显示阶段：数据库快照、对象处理、上传/写入、验证、发布清单。

## 12.28 恢复与合并

### 检查

输入恢复密码后检查账本 ID、本位币、版本、完整性、附件和保险库内容。错误密码不显示哪一部分正确。

### 模式

- 替换恢复：明确当前账本将被备份快照替换，恢复前创建安全快照；
- 合并恢复：只允许相同账本 ID 和本位币，说明可能出现冲突。

### 冲突

三方对比显示共同祖先、本机、备份。用户选择本机、备份或按可用字段解决。已清除实体的 purge tombstone 优先，页面显示“该项目已被永久清除，不能通过合并恢复重新出现”。

### 进度

阶段：读取/下载、密码验证、对象校验、数据库迁移、完整性检查、投影重建、原子交换。原子交换阶段不可取消。失败时明确显示已回滚到恢复前安全快照。

## 12.29 安全与隐私设置

### 应用锁

开关默认关闭。可选立即、后台 1/5/15 分钟和自定义。显示当前认证能力。测试锁按钮让用户立即验证。应用锁只控制 UI，文案不得暗示后台任务停止或数据库每次都用生物识别解密。

### 屏幕隐私

- 最近任务内容遮挡；
- 可选全应用禁止截屏；
- 保险库始终禁止截屏，不受开关影响。

### 遥测和崩溃

两个独立开关；首次隐私确认前状态为“尚未发送”。队列页只显示白名单事件名、时间、结果和脱敏错误码。关闭后立即清空队列和安装标识，并提示重新开启会生成新标识。

### 本地清除

列出本机账本、附件、密钥和本地备份；明确不删除用户导出文件或 Drive 备份。需要输入确认短语。云端删除在独立流程中再次认证。

## 12.30 卡片保险库

保险库首页默认锁定，只显示可进入的卡片尾号。每个敏感动作单独认证：查看完整卡号、复制完整卡号、查看安全码、编辑内容。认证成功只授权本次动作，不建立通用“已解锁30秒可随意查看”会话。

- 卡号复制后显示清空倒计时；
- 安全码不得复制；
- 30 秒自动隐藏；
- 后台、锁屏、离开页立即隐藏；
- 设备无安全锁时阻止启用并提供系统设置入口；
- 保险库认证不解锁应用，应用锁认证不解锁保险库。

## 12.31 桌面小组件

| 类型 | 推荐尺寸 | 内容 | 点击行为 |
|---|---|---|---|
| 快速记账 | 2×1 / 4×1 | 分类或模板快捷入口 | 打开预填完整表单 |
| 本月消费 | 2×1 | 本月消费、与上月比较 | 打开消费报表 |
| 本月预算 | 2×1 | 已用/可用和进度 | 打开预算 |
| 今日可用 | 2×1 | 今日可用金额 | 打开预算详情 |
| 指定账户 | 2×1 | 账户余额/可用余额 | 打开账户详情 |
| 核心净金融资产 | 2×1 | 指标和变化 | 打开账户首页 |
| 指定信用卡 | 2×1 | 本期剩余应还、到期日 | 打开信用账户 |
| 指定目标 | 2×1 | 目标进度 | 打开目标详情 |
| 财务概览 | 4×2 | 消费、预算、资产、信用卡 | 打开分析或对应模块 |

金额默认隐藏。用户必须在每个组件配置中明确允许显示；应用锁并不会自动修改已授权组件的显示，配置页必须解释此隐私边界。快速记账永不直接写入账本。

# 13. 无障碍、国际化和隐私语义

## 13.1 字体缩放

正式支持系统字体缩放到 200%。测试档位至少：100%、130%、160%、200%。

- 不使用固定文字容器高度；
- 横向信息行在 130% 以上可改纵向；
- 底部导航标签必须保持可读，必要时减小图标与标签间距，但字号不低于 token；
- 金额 Hero 在空间不足时优先换行/纵向，不通过低于 24sp 的自动缩小解决；
- 表格在大字体下允许横向滚动，行高自然增长；
- 图表摘要和数据表必须可在大字体下独立阅读。

## 13.2 TalkBack

### 基本规则

- 每个可操作控件有明确角色、标签、状态和操作。
- 图标与相邻文字表达同一含义时合并语义，避免重复朗读。
- 列表行合并为一个可点击节点，并提供主要金额、账户和状态；内部辅助动作如附件可独立聚焦。
- 错误出现时发送无障碍公告，并将焦点移动到错误摘要或首个字段。
- 长任务进度每增加 5% 或阶段变化时公告，避免每一行都朗读。

### 交易行示例

可访问文本：

```text
支出，餐饮，午餐，公司食堂，现金钱包，负一千二百五十日元，包含附件，7月31日12点30分。双击查看详情，长按选择。
```

### 分类卡片示例

```text
午餐，支出二级分类，未选中。双击选择。
```

一级分类：

```text
餐饮，支出一级分类，可直接记账，包含4个二级分类。
```

### 金额隐藏

隐藏时只读“金额已隐藏”，禁止语义树、测试标签和内容描述包含原值。

## 13.3 焦点顺序

- 遵循视觉从上到下、从左到右；
- 固定 FAB 在内容字段之后、底部导航之前；
- 模态打开时焦点限制在模态内；
- 模态关闭后返回触发控件；
- 地图默认作为一个整体节点，用户进入地图探索模式后才聚焦点和控件；
- 图表默认先读标题和摘要，再提供“探索图表”和“查看数据表”。

## 13.4 非颜色语义

必须通过灰度截图测试：

- 收入/支出/退款/转账仍可通过正负号、图标和文字区分；
- 预算正常/接近/超支有文字；
- 图表系列使用直接标签、点形或虚线作为辅助；
- 选中项有描边和勾选；
- 错误有图标和文字。

## 13.5 减少动画

读取系统减少动画设置和应用设置。开启后：

- 页面切换直接或 80ms 淡入；
- 折叠区直接展开；
- 图表不做绘制动画；
- 地图聚类变化不做夸张飞行动画；
- 保存成功只显示静态勾选/Snackbar。

## 13.6 三语和地区格式

首批语言：简体中文、日语、英语。

- 所有可见文本来自资源，不允许 Kotlin 硬编码；
- 复数、日期、货币和数字使用 locale API；
- 术语表集中管理，尤其是“费用/消费”“账单/还款”“互请/结算”“目标资金”；
- 英文按钮不得强行大写；
- 日语长复合词允许自然换行；
- 图表轴标签使用 locale 简写，但 TalkBack 使用完整格式；
- 用户可覆盖应用语言、日期格式和一周起始日，币种格式默认跟随选择的地区规则。

## 13.7 隐私语义

以下信息不得出现在未加密 SavedState、route、test tag、contentDescription、日志、遥测或崩溃 message：

- 金额；
- 账户/卡片/商户/项目/参与人名称；
- 备注；
- 经纬度；
- 附件名称和路径；
- 卡号、安全码；
- 备份密码。

测试标签使用稳定语义 ID，例如 `transaction_amount_field`，不得拼接实际值。

# 14. 图表和地图详细契约

## 14.1 图表颜色序列

图表只使用 `chart.categoricalLight/Dark` 或顺序色阶。顺序按数据系列稳定 ID 生成，过滤和排序后同一系列保持颜色一致。收入、费用等语义可以使用对应语义色作为单系列，但多系列对比不得把红/绿作为唯一差异。

## 14.2 线图

- 主线 2dp，选中线 3dp；
- 数据点默认隐藏，点较少或选中时显示 6dp；
- 多系列使用点形/虚线辅助；
- Y 轴从零开始仅在业务合理时使用；余额趋势可使用紧凑范围，但必须显示基线说明；
- 缺失数据断线，不自动当作零。

## 14.3 柱状图

- 柱间距至少 4dp；
- 正负值以零轴分隔；
- 堆积图各部分总计可通过 marker 查看；
- 类别标签过长时旋转不是首选，优先使用横向条形图；
- 小于一个像素的非零值仍通过 marker/表格可访问。

## 14.4 饼图

- 最多 6 个扇区；
- 其他类别合并为“其他”；
- 不使用 3D、爆炸、阴影；
- 扇区必须有外部标签或图例与精确值；
- 类别超过限制自动改为条形图，UI 说明原因。

## 14.5 预算和目标进度

- 优先线性进度，不用仪表盘作为唯一表达；
- 环形图只作为小型补充，中心显示精确值；
- 超过目标/预算后保持满格并显示超出；
- 负结转通过独立数值，不绘制负环。

## 14.6 Marker

Marker 至少显示：维度标签、完整金额、比较值、系列名。可通过拖动或左右键/无障碍动作切换。Marker 不遮挡主要数据时优先置于上方；屏幕边缘自动翻转。

## 14.7 地图覆盖层

- 聚类圆直径 36/44/52dp，对应低/中/高数量；数字始终可读；
- 单点使用 32dp pin；选中点 40dp；
- 热力图使用透明到深青绿的顺序色阶；
- 金额模式和笔数模式在控件中明确标注；
- 用户位置与交易位置使用不同图形；
- 不使用分类全色绘制每个点，避免地图噪声；
- attribution 始终可见或通过标准信息入口可达，不能遮挡。

# 15. Compose 实现契约

## 15.1 Theme API

建议公开结构：

```kotlin
@Immutable
data class LedgerColors(
    val material: ColorScheme,
    val positive: SemanticColor,
    val warning: SemanticColor,
    val danger: SemanticColor,
    val info: SemanticColor,
    val neutralTransaction: SemanticColor,
    val chart: LedgerChartColors,
    val categoryPalette: ImmutableList<CategoryColorPair>,
)

@Immutable
data class LedgerDimensions(
    val pageHorizontalPadding: Dp,
    val touchTargetMin: Dp,
    val formFieldMinHeight: Dp,
    val bottomActionInset: Dp,
    // 只映射 token，不允许 feature 创建局部值
)

@Composable
fun LedgerTheme(
    themeMode: ThemeMode,
    dynamicColor: Boolean,
    reduceMotion: Boolean,
    content: @Composable () -> Unit,
)
```

Material 3 `ColorScheme` 作为底层实现，但 feature 只通过 `LedgerTheme` 和包装组件访问业务语义。

## 15.2 组件 API 原则

- 状态提升：可复用组件接收 value/state 和事件，不持有 ViewModel。
- 不接受任意 `Color`、`Shape` 或 `TextStyle` 参数；需要变体使用封闭枚举。
- `Modifier` 始终为第一个可选参数，并只允许布局/测试/无障碍增强，不得绕过内部最小尺寸。
- 业务组件使用 `@Immutable` UI model。
- 事件命名使用用户意图：`onSave`, `onSelectCategory`, `onRevealPan`，不使用 `onDatabaseUpdate`。

示例：

```kotlin
@Composable
fun CategoryTile(
    model: CategoryTileUiModel,
    selected: Boolean,
    onClick: () -> Unit,
    modifier: Modifier = Modifier,
)

@Composable
fun AmountText(
    model: MoneyUiModel,
    size: AmountSize,
    modifier: Modifier = Modifier,
)
```

## 15.3 Screen API

每个 feature 暴露：

```kotlin
object RecordRoutes {
    val Home = RouteKey("record/{tab}")
    val Editor = RouteKey("record/editor/{mode}/{transactionId?}")
}

fun EntryProviderScope.recordDestinations(
    navigator: AppNavigator,
)
```

feature 不直接 import 其他 feature 的内部 route 或 Composable；跨 feature 使用 `:core:navigation` 定义的公共 destination contract。

## 15.4 UiState 和 UiAction

每个 screen 定义单一 `UiState` 和封闭 `UiAction`：

```kotlin
@Immutable
data class JournalUiState(
    val loadState: LoadState,
    val activeFilter: FilterSummaryUiModel,
    val selection: SelectionUiState,
    val amountVisibility: AmountVisibility,
)

sealed interface JournalAction {
    data class OpenTransaction(val id: StableId) : JournalAction
    data object OpenSearch : JournalAction
    data object OpenFilter : JournalAction
    data class ToggleSelection(val id: StableId) : JournalAction
}
```

禁止多条互相矛盾的 StateFlow 分别驱动同一屏幕。一次性导航和消息使用受控 effect，不把整个状态重发成事件。

## 15.5 文案和错误

- 使用 `UiText.Resource` 或等价类型；
- DomainError/DataError/ExternalError 映射到固定 `UiErrorCode`；
- 不显示 exception.message；
- 格式化金额/日期在 application/presentation mapper 完成；
- 翻译资源 key 稳定，禁止根据英文字符串做逻辑判断。

## 15.6 列表和 Paging

- 使用稳定 key；
- content type 区分日期头、交易行、加载行；
- 不在 Composable 中将 PagingData 转成完整 List；
- 不在每次重组中格式化大量金额；
- 日期分组由查询/mapper 提供；
- 滚动位置以稳定 key 恢复；
- 全选查询结果由 selection spec 表达，不维护 50 万 ID 集合。

## 15.7 表单

- `TransactionEditor` 的 reducer 纯粹处理 UI 草稿和字段联动；
- 账务计算、退款额度、贷款分配、不变量验证由 application/domain；
- UI 可以做格式级预校验，但不得自行生成 Journal/Posting/Effect；
- 自动默认值只在用户未触碰字段时应用；
- 编辑历史交易时使用当前修订完整快照初始化。

## 15.8 敏感状态

- 金额、备注、卡号、位置不进 `SavedStateHandle`；
- 保险库明文使用最小生命周期对象，离开 Composable/后台立即清除；
- 预览图像缓存锁定时清理；
- Preview/截图测试数据必须是显式虚构 fixture，不能从真实数据库读取；
- test tag 不包含实际值。

## 15.9 MapLibre 包装

`:core:geo` 提供 `LedgerMap`，统一管理：

- MapView 生命周期；
- 样式加载；
- attribution；
- 聚类/热力图 source/layer；
- Compose state 到 MapLibre 更新的差异化应用；
- 可访问替代列表；
- 主题和减少动画；
- 内存释放。

feature 不得直接添加任意颜色和 layer ID。

## 15.10 Vico 包装

`:core:designsystem` 或统一 chart 包提供：

- `LedgerLineChart`
- `LedgerColumnChart`
- `LedgerStackedChart`
- `LedgerPieChart`
- `LedgerChartCard`
- `LedgerAccessibleDataTable`

统一 marker、颜色、轴、网格、空态和 TalkBack。feature 只传类型化 series/model。

## 15.11 Glance

小组件只读取 widget snapshot。Glance 组件使用与应用相同语义色和字号比例的受限子集，不复制完整 Compose 页面。配置活动使用普通 Compose 设计系统；小组件本体遵守 RemoteViews/Glance 限制。

## 15.12 Preview 和示例数据

每个公共组件至少有：

- 浅色 Preview；
- 深色 Preview；
- 200% 字体 Preview；
- 简中/日语/英语长文案 Preview；
- 错误/禁用/选中适用状态 Preview。

示例数据集中放在 `:core:designsystem` preview fixtures，不在 feature 私自创建风格不同的数据。

# 17. 完成定义（Definition of Done）

一个页面只有同时满足以下条件才视为完成：

1. 使用登记的 screen ID 和 route contract；

7. TalkBack、触控目标和非颜色语义通过；
8. 无敏感 SavedState、route、日志或语义泄漏；
9. 截图基线通过；
10. Compose UI 测试覆盖主操作和错误路径；
11. 大列表/长任务符合性能和取消规则；
12. 产品文案不改变账务语义；
13. 需求追踪矩阵对应项已标记通过；
14. 不存在 feature 局部“临时组件”。

# 18. UI 派生决策记录

以下决定是为了把已冻结需求转化为可实现 UI 而新增，不改变领域模型：

| ID | 决策 | 理由 |
|---|---|---|
| UI-ADR-001 | 顶层页面右上固定“更多功能”入口 | 需求规定五个底部入口，其他模块需稳定可达；避免抽屉和不同页面入口漂移 |
| UI-ADR-002 | 不使用滑动删除财务记录 | 降低误触，回收站和依赖处理需要显式流程 |
| UI-ADR-003 | 分类一级组＋同组件可选卡片 | 同时满足两级层次、一级可直接记账和网格复用 |
| UI-ADR-004 | 未保存表单进程死亡后丢弃并说明 | 架构禁止敏感 SavedState，产品不支持草稿 |
| UI-ADR-005 | 普通表单无效时保存按钮仍可点击并显示错误 | 避免无解释禁用；领域前置条件缺失时才真正禁用 |
| UI-ADR-006 | 长操作统一操作中心 | 导入、导出、备份和恢复均有持久状态，统一状态语言减少漂移 |
| UI-ADR-007 | 交易列表不支持滑动快捷编辑/删除 | 复杂依赖和版本历史需要详情或选择模式 |
| UI-ADR-008 | 地图失败提供列表替代 | 地图是外部能力，不应阻断本地数据阅读和无障碍 |
| UI-ADR-009 | 互请可显示由领域服务提供的结算建议 | 净额结算需要可操作建议；UI 不自行写账或改变不变量 |
| UI-ADR-010 | 报表类别超过6时饼图自动改条形图 | 已冻结需求明确要求类别多时自动更换，统一阈值避免页面自行判断 |
| UI-ADR-011 | 顶层采用小型固定 App Bar，不使用大标题折叠 | 平衡信息密度，并让录入、列表和分析保持同一外壳 |
| UI-ADR-012 | 设计令牌 JSON 为机器可读唯一值 | 避免文档、Compose 和图片样稿出现三套不同数值 |

# 19. 禁止实现清单

开发和 vibe coding 过程中，以下实现即使“看起来能用”也必须拒绝：

- 每个页面自行创建 Card、TextField、Button 样式；
- 默认 Material 3 颜色直接混入 feature；
- 支出全部红色；
- 分类整卡高饱和颜色；
- 分类重新选择改为 DropdownMenu；
- 互请区域默认全部展开；
- 保存按钮随内容滚走；
- 自制数字键盘；
- 在 route 或 SavedState 保存金额、备注、位置或卡片信息；
- 在流水行滑动永久删除；
- 把信用卡还款或贷款本金显示成费用；
- 把退款显示成收入；
- 把自动生成记录称为现实付款成功；
- 用“净资产”暗示包含房产、投资等未管理资产；
- 把计划还款显示在当前流水；
- 候选记录进入余额、预算或报表；
- 关闭地图后让消费地图页面完全不可用；
- 图表无文字摘要和数据表；
- 饼图无限增加扇区；
- 保险库一次认证后长期保持全部内容可见；
- 安全码提供复制；
- 高风险操作只弹一个普通确认框；
- 大型导入/备份只显示无限转圈；
- 为了快速实现而在 feature 内复制设计系统组件。

# 21. 最终冻结结论

本软件的 UI 统一规则为：

> **全应用只存在一套“静稳精确”设计系统；以深青绿作为可替换的品牌外壳，以中性表面承载高密度财务信息，以受控语义色区分收入、退款、警告和危险；分类、金额、账户、交易行、表单、筛选、图表、地图、长任务和安全界面均使用中央组件。任何 feature 不得拥有自己的视觉语言。**

开发实现应以以下顺序落地：

1. token 与 `LedgerTheme`；
2. 核心外壳、导航、状态和基础组件；
3. 分类网格、金额输入、交易编辑器和流水行；
4. 账户、预算和分析基础页面；
5. 信用、贷款、互请、项目、目标和自动化；
6. 导入、导出、备份、恢复、保险库和小组件；
7. 全矩阵截图、无障碍、性能和需求追踪验收。

未经版本化评审，不得在开发阶段改变上述视觉语义、字段顺序、导航位置、组件来源或高风险交互。
