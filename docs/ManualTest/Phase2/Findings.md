# ExpenseTracker 第二轮手动测试问题记录

## 文档约定

- `MAN-P2-*`：用户在第二轮手动测试中发现的问题。
- 严重度：`P0` 无法继续或造成数据/安全灾难；`P1` 发布阻断；`P2` 明显功能或体验缺陷；`P3` 轻微一致性问题。
- 本文档只记录问题，不包含修复。本轮未读取源码验证原因，也未修改实现。
- 下列复现信息和现状均来自用户的手动测试反馈，后续修复前仍应在最新安装包中逐项复现并补充设备、系统版本、日志或截图证据。

## 发现清单

### MAN-P2-001｜P1｜分类预算为 0 时页面持续显示加载动画，且已设置的分类预算无法取消

- 状态：待修复
- 涉及页面：预算页面、分类预算设置/编辑页面。
- 前置条件：某个分类已经设置过单独的分类预算。
- 复现步骤：
  1. 将该分类的预算金额设置为 `0` 并保存。
  2. 返回预算页面，查看“分类预算”区块中该分类的卡片。
  3. 同时观察“本月剩余可用预算”卡片中的“已用”区域。
- 项目现状：
  - 分类卡片仍能正常显示该分类的“已用”“可用”等数据，但在这些数据与“未单独设置预算，消费仍占用月度总预算”提示文字之间会一直显示加载动画，无法结束。
  - “本月剩余可用预算”卡片的“已用”内容下方也有概率出现相同的持续加载动画。
  - 把分类预算重新设置为非零金额后，持续加载现象消失。
  - 一旦为分类设置过预算，当前没有可发现的删除、清除或恢复为“未单独设置预算”的方式；用户只能输入 `0`，而这又会触发上述异常。
- 用户影响：页面看起来始终处于未完成的加载状态，用户无法判断数据是否已经稳定；同时，已经创建的分类预算无法撤销，预算配置不可逆。
- 正确需求：
  - `0` 或空金额应被视为“未单独设置分类预算”，并清除该分类已有的独立预算配置；界面也应提供明确、可发现的“清除预算/不设置预算”能力。
  - 未单独设置分类预算时，该分类的消费仍应计入月度总预算，并稳定显示对应的已用/可用信息与说明文字。
  - 页面完成数据计算或加载后不得残留无限旋转的进度指示；“本月剩余可用预算”卡片也必须遵守同一状态规则。
  - 设置、清除以及再次设置分类预算都应可重复执行，不应要求用户用非零金额规避异常。
- 验收方向：分别验证“从未设置”“设置非零值”“非零改为 0”“非零清空”“清除后再次设置”五种状态，并确认刷新、离开后返回及重启应用后均无无限加载，预算汇总数据一致。

### MAN-P2-002｜P1｜分析周期无数据时周期选择控件消失，用户无法切回其他周期

- 状态：待修复
- 涉及页面：分析页面。
- 复现步骤：
  1. 进入存在分析数据的周期。
  2. 使用周期调整组件切换到一个没有分析数据的周期。
- 项目现状：页面切换为空状态后，只显示“还没有可分析的数据”，原先用于调整周期的组件同时消失。用户无法在当前页面把周期切回有数据的范围，只能退出页面或采用其他绕行方式。
- 用户影响：一次正常的筛选操作会把用户困在不可恢复的空状态中，分析页面的核心导航中断。
- 正确需求：周期调整组件必须是分析页面的常驻控制项，无论当前周期处于加载、成功、有数据、无数据或错误状态都应保持可见且可操作。空状态信息应显示在周期组件下方，用户可以直接切换到任意其他周期并恢复分析内容。
- 验收方向：连续切换“有数据 → 无数据 → 有数据”以及多个相邻空周期，确认周期组件始终保留、当前周期显示正确，返回有数据周期后图表和汇总正常恢复。

### MAN-P2-003｜P2｜记账页底部白色遮罩遮挡内容，保存按钮没有真正悬浮在页面上

- 状态：待修复
- 涉及页面：记账页面，尤其页面底部与保存按钮所在区域。
- 项目现状：页面最下方、与保存按钮高度接近的位置存在一块白色遮罩。保存按钮视觉上或布局上落在该遮罩之上，而不是直接悬浮在可滚动内容上；遮罩会覆盖其下方的表单信息。
- 用户影响：底部内容被不必要地遮挡，用户可能误以为页面已经结束或无法查看被覆盖的信息；悬浮保存操作的视觉层级和空间利用也不符合预期。
- 正确需求：删除保存按钮背后的不透明白色遮罩，让保存按钮作为独立的悬浮操作显示在页面内容上方。可滚动内容必须能够滚动到按钮和系统底部安全区之外，最后一项信息可完整查看和操作；按钮本身仍需保持清晰、可点击，并正确避让系统导航栏与输入法。
- 验收方向：在收入、支出及其他共用记账编辑器的页面中检查长短表单、滚动到底、输入法展开/收起和不同系统导航模式，确认没有白色底板遮挡信息，最后一项字段与保存按钮均可到达。

### MAN-P2-004｜P1｜收入或支出记录页面点击账户后应用直接闪退

- 状态：待修复
- 涉及页面：新建或编辑收入记录、新建或编辑支出记录的账户选择入口。
- 复现步骤：
  1. 打开收入记录页面或支出记录页面。
  2. 点击“账户”字段，尝试选择入账或扣款账户。
- 项目现状：点击账户字段后，应用直接闪退，账户选择界面无法使用。
- 用户影响：收入和支出无法正常选择账户，核心记账流程被阻断；若编辑已有记录，也可能导致用户尚未保存的输入丢失，属于发布阻断问题。
- 正确需求：点击账户字段应稳定打开符合当前交易类型的账户选择界面，显示可用账户、当前选择和必要的搜索/空状态；选中或取消后应安全返回原表单并保留所有已输入内容。无账户、仅一个账户、多个账户以及存在停用账户等边界均不得导致崩溃。
- 验收方向：分别覆盖收入与支出、新建与编辑、空账户列表/单账户/多账户、选择/取消/返回及重复打开选择器；同时确认崩溃不再发生且表单状态不丢失。

### MAN-P2-005｜P2｜新建分类的默认账户选择浮窗布局错乱

- 状态：待修复
- 涉及页面：新建分类页面中的默认账户选择浮窗。
- 复现步骤：
  1. 进入新建分类页面。
  2. 打开“默认账户”选择浮窗。
- 项目现状：浮窗内的搜索栏与账户单选按钮（radio button）位置错乱，控件没有按预期对齐或排列，影响账户列表的阅读和选择。
- 用户影响：用户难以确认搜索区域、账户文字与单选状态之间的对应关系，可能选错默认账户；布局异常也会降低浮窗的可用性和完成度。
- 正确需求：搜索栏应作为独立的顶部搜索区域完整显示；账户列表的每一行应保持一致的水平与垂直对齐，单选按钮、账户名称及辅助信息归属于同一可点击行，互不重叠、不被裁切。选中状态和点击区域应清晰，并在输入法显示、长账户名、大字体和窄屏下保持稳定布局。
- 验收方向：验证无搜索词、有结果、无结果、长账户名、滚动、选中/切换、输入法展开以及大字体/窄屏场景，确认搜索栏和所有单选行位置稳定且触控目标正确。

### MAN-P2-006｜P2｜金额键盘输入运算符时插入位置位于光标之后

- 状态：待修复
- 涉及页面：记账页面的金额输入框及其加、减、乘、除等运算按钮。
- 复现步骤：
  1. 在金额输入框中输入一段数字或算式。
  2. 将光标移动到已有内容的中间。
  3. 点击页面上的加、减、乘或除按钮。
- 项目现状：点击运算按钮后，输出的运算符出现在光标后面，没有按当前光标所指的插入位置进入表达式。
- 用户影响：编辑已有金额算式时，运算符会落到用户预期之外的位置，需要再次移动光标或手动修改，容易形成错误表达式。
- 正确需求：运算符应在当前光标位置插入，即视觉上插入到原光标之前；插入完成后，光标应自然移动到新运算符之后，方便继续输入后续数字。存在文本选区时，应使用运算符替换选中内容，并将光标放到新运算符之后。加、减、乘、除及其他同类快捷输入按钮应遵守一致的光标和选区规则。
- 验收方向：分别在表达式开头、中间、末尾以及存在文本选区时测试所有运算按钮，并覆盖连续插入、删除后插入和移动光标后插入，确认表达式内容及最终光标位置都符合预期。

### MAN-P2-007｜P1｜首次授权位置权限后必须点击两次“使用此位置”才能保存并返回

- 状态：待修复
- 涉及页面：从记账页面进入的位置页面，首次请求位置权限的流程。
- 前置条件：应用尚未获得位置权限。
- 复现步骤：
  1. 从记账页面首次进入位置页面。
  2. 在系统权限弹窗中允许位置权限。
  3. 定位完成后点击“使用此位置”。
- 项目现状：第一次点击“使用此位置”不会完成位置记录并返回记账页面，必须再次点击同一按钮才能保存位置并返回。
- 用户影响：主要操作第一次点击没有反馈或没有生效，用户可能误以为定位结果不可用、按钮失效或保存失败；也增加了重复提交和流程中断的风险。
- 正确需求：权限授予后的页面状态应立即与最新权限及定位结果同步。当“使用此位置”按钮处于可用状态时，首次点击就必须保存当前位置、结束本次位置选择并返回原记账表单；返回后应显示刚刚保存的位置。按钮点击期间应避免重复提交，但不得要求用户再次点击才能完成。
- 验收方向：覆盖首次允许精确位置、首次允许大致位置、先拒绝后在系统设置中允许，以及权限已经存在的流程；每种情况下都确认一次点击即可保存并返回，原记账表单内容不丢失且位置状态正确。

### MAN-P2-008｜P1｜定位达到等待上限后永久停止，失败状态下无法继续或手动重试

- 状态：待修复
- 涉及页面：记账页面的位置获取流程、位置编辑页面。
- 项目现状：一次定位达到当前等待上限后，应用会停止记录位置；即使用户仍停留在本次记账流程中，也不会继续尝试获取位置。定位失败后，用户在位置编辑页面中也没有手动重试入口，因而无法在环境改善后重新获取位置。
- 用户影响：室内、冷启动、信号较弱或系统刚授权权限时，短暂超时会使本次记账永久失去位置记录机会；用户只能离开流程或重新操作，且无法明确控制重试。
- 正确需求：
  - 每次定位尝试的等待上限应调整为 15 秒。
  - 只要本次记账表单仍然存在、尚未成功获得位置且用户没有保存或退出，就应继续尝试获取位置，直到成功为止；单次达到 15 秒只结束当前尝试，不应让整个位置获取流程永久停止。
  - 定位尝试必须具有明确的生命周期：用户点击记账保存按钮后，无论定位是否成功，都应立即停止后续定位与自动重试，不得延迟保存，也不得在页面离开后继续无意义地请求位置。
  - 位置编辑页面必须提供清晰的“重试定位”按钮，使用户可以在失败或超时后主动重新发起一次定位；重试时应显示新的获取状态并防止重复并发请求。
  - 权限被拒绝、定位服务关闭等不可通过普通重试恢复的状态，应显示对应原因和可执行的处理入口，而不是无休止地静默重试。
- 验收方向：模拟立即成功、单次超过 15 秒后下一次成功、连续多次超时、权限拒绝、定位服务关闭、进入后台、离开页面以及定位中直接保存等场景；确认自动重试、手动重试和停止条件都准确，且同一时刻不存在多个并发定位请求。

### MAN-P2-009｜P2｜记账页面的位置入口长期显示“正在获取位置”，未反映真实状态

- 状态：待修复
- 涉及页面：记账页面的位置记录入口及其状态摘要。
- 项目现状：位置入口似乎一直显示“正在获取位置”，没有根据实际流程切换为“已获取位置”“获取失败”等状态；因此入口显示可能与后台真实定位状态不一致。
- 用户影响：用户无法判断位置是否已经成功记录、是否需要等待、是否失败或是否需要采取重试/授权等操作，也难以在保存记账前确认最终会不会附带位置。
- 正确需求：位置入口必须由真实的位置获取状态驱动，并至少清楚区分：未请求、正在获取、已获取、等待超时/获取失败、权限被拒绝、定位服务不可用以及用户未记录/已清除位置。成功状态应显示可识别的位置摘要；失败状态应提供原因或下一步操作；正在获取状态只能在确有活动请求或计划中的自动重试时显示。状态变化应及时更新，并与位置编辑页面及最终保存结果保持一致。
- 验收方向：逐一触发所有位置状态及其转换，特别验证“正在获取 → 已获取”“正在获取 → 超时后重试”“失败 → 手动重试 → 已获取”“获取中直接保存”和“已获取后清除”，确认入口文案、图标、可点击动作及最终记录内容始终一致。

### MAN-P2-010｜P2｜从子页面返回记账页面时金额框重复自动聚焦并弹出输入法

- 状态：待修复
- 涉及页面：记账页面及其账户、实体卡等属性选择子页面。
- 复现步骤：
  1. 进入记账页面，金额文本框自动获取焦点并弹出输入法。
  2. 完成金额输入，使金额框失去焦点或进入账户、实体卡等其他属性页面。
  3. 返回仍在编辑中的记账页面。
- 项目现状：记账页面每次重新出现在屏幕中时，金额文本框都会再次自动获取焦点并弹出输入法，即使用户已经完成金额输入并正在处理其他属性。
- 用户影响：输入法反复弹出会遮挡表单内容和返回后的目标区域，打断账户、实体卡等属性的连续编辑；用户还需要额外关闭输入法才能继续操作。
- 正确需求：
  - 新建记账表单首次显示时，金额文本框应自动获取焦点并弹出输入法，保留当前便捷录入行为。
  - 首次自动聚焦只能发生一次。金额框失去焦点后，从账户、实体卡、分类、位置或其他属性子页面返回时，不得再次自动请求焦点或弹出输入法。
  - 返回记账页面时应保留金额、光标/选区及其他表单内容，但默认恢复到非输入法遮挡的表单浏览状态；只有用户再次主动点击金额框时才重新弹出输入法。
  - 屏幕旋转、进程状态恢复或导航回栈重组不得把已经消费过的“首次自动聚焦”事件重复执行。
- 验收方向：分别验证首次进入、主动关闭输入法、点击其他字段、依次进入并返回账户/实体卡/分类/位置等子页面、旋转屏幕及后台恢复；确认只有首次进入或用户主动点击金额框时才弹出输入法，表单数据始终保留。

### MAN-P2-011｜P1｜应用锁认证成功后仍停留在“应用已锁定”加载画面

- 状态：待修复
- 涉及页面：开启应用锁后的锁定页面与认证返回流程。
- 前置条件：已在设置中开启应用锁，应用进入需要认证的锁定状态。
- 复现步骤：
  1. 打开处于锁定状态的应用。
  2. 按系统认证流程成功完成身份验证。
- 项目现状：系统认证已经成功，但应用画面仍停留在“应用已锁定”，并持续显示旋转的加载状态，无法进入应用内容。
- 用户影响：开启应用锁后，合法用户即使认证成功也无法使用应用，形成无法自行恢复的核心流程阻断；用户可能只能强制关闭应用或停用安全功能。
- 正确需求：认证成功结果必须被应用锁状态机准确消费，并立即把当前会话切换为已解锁状态，结束加载、移除锁定遮罩并恢复到认证前的目标页面。认证成功不得再次触发并发认证或被旧的锁定/加载状态覆盖。认证取消、失败、系统错误和超时应分别回到可重试且不持续转圈的明确状态；应用进入后台后是否重新上锁应遵循已配置策略，但不能影响刚完成的成功解锁。
- 验收方向：覆盖生物识别成功、设备凭据成功、首次失败后成功、取消后重试、认证期间切换前后台、应用冷启动及已打开页面重新上锁；确认成功后一次解锁即可进入原页面，失败分支可恢复，任何状态都不会无限加载。
