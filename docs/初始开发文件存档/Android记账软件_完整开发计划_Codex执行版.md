## 2. “完整完成”的可验证定义

项目只有同时满足以下条件才可称为完成：

- 90 项需求全部 VERIFIED，并绑定可重复测试证据。
- 215 个页面、模式、弹窗和系统流程全部 VERIFIED；route、参数、结果、组件、requiredStates 和 notes 均与 YAML 对齐。
- 领域模型中的 35 项永久不变量全部有领域测试、数据库审计或恢复验证证据。
- 全部 Current/Revision/Fact/Projection/Operation 表、索引、FTS5、R*Tree、迁移和投影与逻辑模型一致。
- 所有正式财务操作平衡；编辑、删除、恢复、批量、导入、周期、合并和清除均幂等、原子且可审计。
- 数据库、附件、缩略图、暂存、备份和敏感设置静态加密；保险库与普通账本密钥和解锁状态分离。
- 简体中文、日语、英语、浅色/深色/动态色边界、320dp、200% 字体、TalkBack、减少动画和非颜色唯一表达通过。
- 50 万交易、200 万事实/历史、10 万行导入、5 万附件文件、1 万地点和数十 GB 流的性能/故障门通过。
- release AAB、Baseline Profile、依赖锁、SBOM、许可证、开源 NOTICE、隐私文档和构建说明齐全。
- 生产代码中无 TODO、NotImplemented、空壳、假数据、临时组件、调试后门、动态依赖或规格外功能。

## 4. 工具、依赖与停止规则

- Gradle/Maven 项目库、插件和依赖由 Codex 自行添加和下载，无需报告。
- 若需要操作系统级、SDK/IDE 级、设备级或独立软件而当前电脑没有，Codex 必须立即停止，不得降级到功能更弱的工具；报告缺失项、推荐版本、用途、验证命令和恢复入口。
- 真机要求不能用 Robolectric 或普通 JVM 测试替代。
- 用户专属发布凭据（签名、Drive OAuth、遥测/崩溃端点等）属于外部发布输入；代码必须完整、可配置且不硬编码假凭据。
- 不得使用 `git reset --hard`、删除未说明改动或覆盖用户工作；应在当前状态上审计、整合和修复。

### P03 — 核心值对象、金额、时间与确定性算法

**依赖：** P02  
**主要需求：** REQ-014、REQ-015、REQ-024、REQ-025、REQ-030；支撑全部财务不变量  
**页面/流程：** 后续所有金额、时间和周期相关页面的核心能力  
**目标：** 完成不依赖 Android 的精确数值、时间和标识基础，消除浮点、溢出、时区和表达式歧义。

**必须形成的结果**

- 实现稳定 ID/Internal ID、受检算术、错误模型、不可变结果类型和可测试 Clock/ID 来源。
- 实现 `Money(Long minor + CurrencyCode)`、法定货币元数据、精确舍入、BigDecimal/BigInteger 运算、FX 证据和值对象。
- 实现有限金额表达式 tokenizer/parser/evaluator，支持规定运算符、全半角规范化、本地小数分隔符、错误位置和货币最小单位。
- 实现 Instant/ZoneId/ZonedDateTime/LocalDate/YearMonth 等时间模型、账单周期和预算月份工具。
- 实现统一格式化接口，UI 层只接收格式化 UI model，不在 Composable 中做权威计算。

**阶段验收门**

- 权威金额路径不存在 Float/Double；所有 Long 累加有溢出检测。
- 表达式性质测试覆盖合法/非法输入、除零、极值、全角符号、三种语言地区格式和舍入。
- 跨时区、跨日、DST、账单周期和自然月边界测试通过。
- 核心模块保持纯 Kotlin，无 Android/Room/网络依赖。

**本阶段重点阅读：** 技术栈第六节、领域模型核心值对象与时间/金额章节、需求金额与时间章节。

- P31：RST-001—RST-007、JRN-012 最终清除、CLR-002、G-004/G-005 恢复集成。
- P32：VLT-001—VLT-004、SETG-006—SETG-011、CLR-001、SYS-004、G-002 安全闭合。
- P33：WGT-001—WGT-003、SETG-001—SETG-005/008/012、TRF-001、G-006—G-008、SYS-002。
- P34：再次逐项核对并闭合 YAML 中全部 215 项；前述分配不允许成为遗漏其他 requiredStates 的理由。

## 9. 跨阶段质量门

- **每阶段：** 编译、静态检查、相关单元/集成/UI 测试、规格台账更新；任何失败先修复再结束。
- **数据库阶段：** Schema 导出、迁移、SQLCipher 能力、integrity/foreign key、Journal 平衡、投影重建。
- **财务阶段：** property test、幂等、expectedRevision、回滚、历史不被当前默认/汇率静默改写。
- **UI 阶段：** screen ID/route/state、唯一设计系统、三语、200% 字体、TalkBack、灰度、减少动画、敏感语义审计。
- **外部能力：** 离线/权限拒绝/授权过期/网络失败是正式状态，不得使本地核心功能失效。
- **长任务：** 持久化 operation、明确阶段和进度、取消能力、不可取消提交阶段、崩溃恢复、临时清理。
- **最终：** API 28/API 36 实体设备、目标规模、故障注入、release AAB、SBOM/许可证/依赖锁。

## 10. 不得接受的“完成”方式

- 只创建模块、接口、空页面或假数据，声称“后续接入”。
- 使用视觉样稿抄像素，绕过 token/契约。
- 为快速开发在 feature 复制组件或引入第二套主题。
- 让 ViewModel、Worker、导入器直接写财务表。
- 以删除旧行代替修订/冲销，或使用 destructive migration。
- 将候选/计划当作正式交易，把退款当收入，把还款/本金当费用。
- 把所有数据读入内存，使用深 OFFSET，或让十万行/数十 GB 任务只显示无限转圈。
- 用测试 mock 代替生产实现，或因缺工具降级到下位方案。
- 只通过 happy path，未覆盖权限、离线、冲突、失败、恢复、极值和大字体。
- 把没有测试证据的条目标为 VERIFIED。

## 11. 外部发布输入（不属于代码缺口）

- 最终 applicationId/Play 列表身份及 Play App Signing 配置。
- Google Drive Authorization 所需 OAuth 客户端配置和与签名匹配的凭据。
- 自托管遥测/崩溃白名单接收端 URL、证书和服务端保留策略；服务器实现本身不在 Android 项目技术边界。
- 正式隐私政策 URL、开源仓库 URL、支持联系方式和商店素材。
- 至少 API 28、API 36 实体设备及用户选择的发布签名/密钥保管方式。

这些输入缺失时，Codex 应完成所有可配置客户端代码和测试，并在 P36 精确列出外部输入；不得硬编码虚假凭据或以无效假服务宣称功能完成。
