# 新增命令适配器检查表

适用：云端办理阶段 3–8 的每个命令及已有命令的扩展。以本机注册表、共用业务操作和结构化确认模型为准；下列项目必须逐项核对，不用增加穷举边界测试。

## 输入与能力说明

- [ ] 注册名称、语义版本、输入 schema、输出引用类型和正常示例；未知命令/版本/字段整批拒绝。金额为最小单位整数，汇率为十进制字符串。
- [ ] 写明必填、默认值、遗漏与显式 null 的差别，以及未知金融值的处理。不得编造本金、费率或历史事实；助手可按用户陈述与协议约定推断当前日期、默认方式并在message列假设（仍显式填写必填字段），未知可空政策保持null，不妨碍允许保存的操作。明确无欠款的0是有依据的提议，相关USER_FACT仍由手机勾选。
- [ ] 引用只能指向前序步骤，类型必须匹配。选择器首次预览解析成固定 ID 集合；确认不得重新扩大目标。
- [ ] 能力清单说明命令的业务含义、限制、前提、连带影响、确认类型、比较字段、执行方式、逆操作或不可撤销原因（`undo`）、失败/资料不足时的处理，并提供可用示例。更新 schema、样例与交接包副本。

## 前提与确认

- [ ] 复用现有 Repository/领域操作，核对账本归属、对象存在/启用状态、来源关系、金额/日期/期限等实际前提。界面和命令使用同一业务校验。`false`/`null` 提交结果必须转为批次失败。
- [ ] 区分三种需用户处理的内容：风险提示遵循已有独立确认策略；必须解决的冲突禁止确认且逐项显示对象/字段/当前值；用户事实声明只能在手机勾选，绑定步骤和条件摘要。普通数值变化无需人为增加风险勾选。
- [ ] `StepEffect` 保留中间状态和连带影响，最终净变化为零也不能省去步骤。预览文字由模型生成，中日文齐全。
- [ ] 比较固定目标及识别事实、每个对象前后绝对值、余额/额度/预算及风险、逐期预测日期/金额/付款账户/规则依据/确认状态；补充新命令特有的业务字段。确认比较不能只用整本账本 digest，也不能比较展示文案。
- [ ] 明确 revision/时间戳语义：确认模型忽略纯审计计数和生成时间；保留还款/退款事实 revision、额度组 revision 等业务依据；保存时间比较排序/默认值语义。日期、时区、恢复期限、办理期限越界单独使预览失效。
- [ ] 新 ID 按“步骤 + 输出角色 + 业务键”映射成占位符；嵌套 JSON 内引用也要规范化。确认执行记录保留占位符到真实 ID 的映射，不能替换用户文本中的字符串片段。

## 撤销与执行

- [ ] 适配器必须实现 `inverse`，由每步前后状态生成逆操作，或返回具体中日文不可撤销原因。动态限制必须在该步骤的预览中可见；一步不可撤销即整批不可撤销。
- [ ] 优先复用现有业务操作；新增对象可以由仅供本机撤销调用的受限移除器整体移除。必须有执行前不存在、执行后完整快照的登记，不能仅凭账户归属认领对象。已有对象恢复原快照，不能用“再算一次”冒充恢复。
- [ ] 正式执行同事务保存逆操作所需前后值、实际 ID、最终目标快照和关联资料。多步修改同一对象时，逆操作按相反顺序执行，冲突基准取整批执行结束后的状态。
- [ ] 撤销预览必须逐项列出“将移除”对象，并以原方案标题标识撤销（不展示 UUID）。撤销仅由本机历史生成方案，不能注册成云端能力；复用 `preview → confirm → run`、锁顺序、事务回滚、确认模型比较和原子提交。局部逆操作适配器只能被本机持久化的撤销方案调用。
- [ ] 在任何逆操作前逐项核对所有受影响对象。记录按完整字段（包括 revision）及关联资料比较；账户/金融对象按完整原始行比较。所有新建对象须复用外键元数据检查方案外引用，并扫描 JSON 内嵌引用和草稿，指出具体引用对象。只允许本方案新建行及将恢复原值的已修改行作为内部引用；从属行/修订也必须单独登记。先恢复已有行，再按外键依赖删除新建行，最后重新统计引用并确认无残留。新命令须定义相应对象的冲突快照，不能仅核对将恢复的单个字段。发现任何冲突，不执行任何步骤。
- [ ] 原方案变为 `UNDONE` 并保存撤销时间，逆向方案保留独立执行记录。原执行快照、来源去重及回执不删除；不能重复撤销或重新执行原方案。本机撤销不发送云端领取回执。
- [ ] 明确 `transactional` / `post-commit` / `interactive`：数据库操作按 `mediaWrites → withTransaction`；网络/文件不能混进事务；提交后效果要入持久队列，交互须说明用户动作。后两类不能因已有队列表就宣称支持撤销，须分别定义可恢复性与失败语义。

## 必要验证与文档

- [ ] 一条代表性组合流程覆盖预览回滚、确认执行、正确的前后业务值。适配器有逆操作时覆盖撤销恢复；无逆操作时覆盖明确拒绝及原数据不变。
- [ ] 一次真实相关对象修改覆盖冲突展示、确认时重跑拒绝及整批不写入；覆盖撤销后去重/不能再次撤销。复用既有共性测试，不为每个适配器复制框架边界测试。
- [ ] 数据库变化补正式迁移及一个保留旧数据的升级用例；UI 变化用相关流程 `looks=all visual=true`，查看三主题中日文截图。Gradle 串行。
- [ ] 更新实现规格、UI 对照、README 测试说明及所在阶段文档；验收结果与实现说明分开。

### 金融规则差异与方案比较展示

`CommandEffectViews` / `CommandFinanceViews` 接入本机共用的 `FinancialDisplayFacts` 只读投影：规则新版本取该步骤 `objects.before` 中同账户同模式最高版本，与新规则比较，首次建立单独标注；方案按存于该步骤办理记录中的 comparison 对齐日期，保留同日多行、账户/组成变化及不完整范围。共用紧凑日期/原/新/差额表，仅将不同的账户或组成列为行下小注；空值与键/嵌套段删除使用不同文案。不得从当前数据库最新规则补基线，不将展示摘要作为业务输入。逐项完整前后值、整批原子性、确认要求、冲突检查和撤销协议保持原样，不新增金融对象直达。验证入口为 `CommandFlowTest#financeCombinationPreviewAcrossLooks`（含同批前序版本与共同月付款比较）。

预测/手填/余额池计划范围、核对字段与额度配置差异共用 `FinancialDisplayFacts`，每一步仅使用该步 `objects.before/after`（含未变化的相关账单），不使用最终净影响或当前数据库替换中间基线。名称也取该步快照。云端顺序为变化摘要 → 风险/缺项/未知 → 比较及逐项完整前后值入口 → 整批事实确认；原计算和归档继续是保存依据，投影不回传业务输入。整批原子性、事实要求、冲突检测、撤销协议和不新增金融对象跳转的决定保持不变。

本机完整依据入口保留逐期账单、组成、付款账户、原预测依据和版本历史；云端“逐项查看前后与连带影响”保留每个字段的前后绝对值。同批前序规则/月付款变更的中间基线由 `CommandFlowTest#financeCombinationPreviewAcrossLooks` 验证，未知/日期/账户差异由 `FinancialDisplayFactsTest` 验证。

循环计划的保留账单范围也由该步池快照中的引用和该步账单快照组成，不能从当前账户补账单。核对只展示适用字段，完整前后输入仍保留在逐项详情。


### 金融 UI 阶段 5 联动

本机批量转换撤销入口在管理 → 办理与版本历史 → 指定批次，循环计划历史也可进入。`financialBatchRevolving.undo` 命令名及输入协议不变，预览从该批次 `BatchArrangementArchive` 生成 `BatchRestorationFacts`（步骤内 `revolvingBatchArchive` 只读展示对象），包括办理时间/批次、原消费及逐笔金额/合计、原一次付、目标循环计划和恢复范围；原撤销事务及全部冲突校验继续执行。该操作称「撤销这次批量转换记录」，执行历史的另一入口称「撤销整份云端方案」，不能互换。完整恢复事实不取当前计划替代归档。

`CommandFinanceViews` 与 `CommandEffectViews` 同步三种 sharing 关系、未配置/未知、跨账户共享组限制及限制后预计可用；上限与可用值分开。金融时间使用步骤捕获的规则时区，平台观测按原时间串偏移，既有 Z 记录显示 UTC，不补造原地区时区；记录时间单列。格式化只影响显示，不进入条件摘要或业务写入，不改变 Instant 精度。

统一「循环还款计划」「本期付款方式变更截止」「核对当前还款安排」「已替换计划」「结账日」「奖金月付款」等名称，`POOL`、枚举、命令、协议、事实确认、原子性和撤销规则不变；仍不新增金融对象跳转。`CommandFlowTest.batchUndoAndLimitRelationshipsUseArchivedFinancialFactsAcrossLooks` 覆盖撤销归档与额度预览；数据回归继续用 `CommandFinanceExecutionTest.poolPaymentBatchConversionAndAuditedRestoration` / `sharedLimitsRecoveryVoidAndActualObservation`。

批次显示以归档办理时间和原消费名称为依据，不输出内部 UUID；原消费按原付款日、名称排序，恢复列表将目标循环计划置后。本机历史仅有“查看并撤销”或已撤销后的“查看”，确认动作在详情内。

额度关系只说明一次，各项上限不在关系与金额摘要中重复。配置预览中变化的上限只在差异区显示，未变化的上限仍在关系区保留：不适用字段不显示，关系切换删除的旧上限仍明确显示旧金额 → 已移除。完整前后依据保留。

云端确认事实会规范化带 ID 的数组；批次摘要在最终展示边界应用同一业务排序，不能依赖序列化顺序。额度追加版本的差异基线取本步骤捕获的 `creditLimit.before.config`（或同一步的旧配置快照），不能把新增存储行的空 before 当成首次配置，也不能查询当前数据库补基线。
