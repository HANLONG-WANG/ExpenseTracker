## 10. 数据格式化与文案契约

### 10.1 货币

- 已核验一致：正常交易与分析主路径使用中央 `LocaleCurrencyFormatter` 和币种元数据，支持不同小数位、locale 符号/分隔、正负语义和金额隐藏。
- 差异：多个页面仍直接展示 minor unit 整数或以字符串拼接币种；流水 mapper 在 formatter 失败时回退为 `${currency.value} $amountMinor`，会把最小单位整数当作用户金额。BUD、LOA/INS/CRD、ANA、导入/恢复等具体实例已在对应页面记录。

### 10.2 汇率

- 已核验一致：外币表单提供缓存/刷新、stale Warning、离线无缓存时的手动输入，人工输入明确说明会覆盖参考证据。
- 差异
  - 原需求：汇率展示统一包含方向、足够精度、来源、报价时间和获取时间，地区化显示且人工证据显示“手动”。
  - 实际行为：`RateRow` 只显示 `1 CODE = BigDecimal.toPlainString() CODE` 和单独的 UTC ISO 报价时间；没有来源与获取时间，尾零/精度没有统一格式器，已输入人工汇率也没有在摘要中以“手动”来源标记。

### 10.3 日期和时间

- 差异：流水日期头使用 locale medium date，设置也支持格式覆盖；但大量详情/表单直接 `LocalDate/Instant.toString()` 或 ISO formatter，未统一实现同年省略年份、跨年含年份、本地发生时间＋时区/offset、账本地区审计时间和 locale 月份格式。各页面章节已记录出现位置。

### 10.4 百分比、利率和权重

- 差异：分析百分比通过 `toPlainString() + "%"` 固定拼接一位小数，没有 locale 百分比格式；多处利率/执行率/权重直接显示 domain decimal 或 minor 数字。虽然贷款/分期字段标签会写“年利率/实际年化利率”，但全局没有统一的 percentage/rate/weight formatter 来保证 0–2 位、地区小数分隔和 `2 : 1 : 1` 权重格式。

### 10.5 交易类型文案

- 差异：规定的中文/日文/英文类型资源存在于部分页面，但流水筛选、交易行、历史/地图明细等路径直接显示 `TransactionKind.name`/kindKey，例如 `EXPENSE`、`FX_EXCHANGE`；违反“内部枚举不得直接展示”。

### 10.6 统计口径文案

一致。消费/非消费费用、退款冲减、信用还款/贷款本金/转账排除、调整/期初余额排除和互请本人承担部分均由 domain/application 的类型化口径提供，未发现 UI 把这些事实改名为相反统计含义。

### 10.7 自动生成文案

一致。自动化区分“正式交易/候选”，并使用“生成记录/待确认”语义；未发现把自动生成描述成银行扣款、支付或现实还款成功。

### 10.8 错误文案

- 已核验一致：原始 exception、SQL、路径、密钥、堆栈和第三方响应正文未直接进入 UI，错误码经过固定/脱敏边界。
- 差异：公共 `LedgerErrorState` 只显示调用方传入的通常为泛化“加载失败”文案、内部 code 和“重试”，许多页面也只有 code Banner；没有系统性说明“发生了什么、是否保存、下一步是什么”。例如 formatter fallback、保存失败与长操作失败普遍缺少是否已写入/是否已回滚的页面级解释，不能满足所有错误文案的三要素。

## 25. 无障碍、国际化和隐私语义（契约第 13 章）

### 13.1 字体缩放

一致。基础组件没有固定文字容器高度，金额 Hero 可自然换行，数据表可横向滚动；源码中的 Preview 覆盖 100%/130%/160%/200%，现有设备测试覆盖 320/360/480/600dp 与最高 200%，本次 API 36、200% 字体下实测的记账首页和更多功能页也保持可读。

### 13.2 TalkBack

- 已核验一致：Material/设计系统控件提供角色与状态；交易行使用合并后的单一可点击语义节点；`ValidationSummary` 使用 Assertive live region；隐藏金额只朗读本地化“金额已隐藏”，其节点和稳定 test tag 不包含原值。
- 差异 1
  - 原需求：错误出现后公告，并把焦点移动到错误摘要或首个错误字段。
  - 实际行为：错误摘要会通过 live region 公告，但全仓生产源码没有 `FocusRequester`、`requestFocus` 或等价焦点移动逻辑；`ValidationSummary` 的点击回调也由调用方自行决定，不能保证错误出现时移动焦点。
- 差异 2
  - 原需求：长任务只在每增加 5% 或阶段变化时公告。
  - 实际行为：`OperationProgressPanel` 整卡直接设为 Polite live region，`contentDescription` 包含每次传入的 processedText；没有 5% 取整、阶段去重或公告节流，任意进度模型更新都可能触发朗读。
- 差异 3
  - 原需求：所有状态语义随当前语言本地化。
  - 实际行为：`LedgerToggleRow` 把 TalkBack 状态硬编码为英文 `on`/`off`；`FormSection` 同样硬编码 `expanded`/`collapsed`。

### 13.3 焦点顺序

- 已核验一致：`LedgerScaffold` 显式设置顶栏、内容、固定操作、底部导航的 traversalIndex，并有设备测试验证“字段 → 保存 → 底栏”；MapLibre 画布默认被合并为一个整体语义节点。
- 差异
  - 原需求：模态打开后限制焦点在模态内，关闭后返回触发控件；图表先读标题/摘要，再提供“探索图表”和“查看数据表”。
  - 实际行为：生产源码没有 focus group、focus restorer、焦点捕获或触发控件恢复逻辑；图表只有整个 renderer 的 summary `contentDescription` 和“查看数据表”，没有“探索图表”动作，也没有可逐点操作的焦点模型。

### 13.4 非颜色语义

- 已核验一致：交易金额使用正负号和类型文字；预算/目标进度有状态及超额文字；选中 Chip/分类有描边或勾选；错误 Banner/状态页有图标和文字，且存在交易行灰度结构测试。
- 差异：多系列 Vico 图表没有直接标签、点形或虚线配置，系列仍只依赖 renderer 默认视觉差异；不满足灰度下系列必须有非颜色辅助语义的要求。

### 13.5 减少动画

- 已核验一致：应用设置有独立 reduceMotion 开关，`LedgerTheme.motion` 能把标准时长收敛到不超过 80ms。
- 差异 1
  - 原需求：同时读取系统减少动画设置和应用设置。
  - 实际行为：根 Theme 只传入数据库设置 `settings.reduceMotionEnabled`；生产源码没有读取系统 animator duration scale 或 `ValueAnimator.areAnimatorsEnabled()`，系统单独关闭动画不会开启该策略。
- 差异 2
  - 原需求：减少动画时地图聚类变化不做夸张飞行动画，同时正常模式保留规定动效。
  - 实际行为：点击 MapLibre 聚类始终调用 `easeCamera`，没有读取 `LedgerTheme.motion.reduceMotion`；反之所有 Vico 图表又始终 `snap()`，正常模式也没有标准动效（另见 `5.6`）。

### 13.6 三语和地区格式

- 已核验一致：简中、日语、英语资源模块通过仓库三语资源闭合校验，英文按钮没有统一强制大写；设置提供语言、日期格式和一周起始日覆盖。
- 差异
  - 原需求：所有可见文本来自资源，日期、货币和数字使用 locale API，TalkBack 状态也须本地化。
  - 实际行为：除各页面章节已记录的 `Enum.name`、ISO 日期/时间和原始 minor unit 外，公共组件仍包含英文 `on/off`、`expanded/collapsed`，页码 `${pageIndex + 1} / $pageCount` 和保险库倒计时 `${secondsRemaining}s` 也直接拼接；这些内容绕过字符串/复数/地区资源。

### 13.7 隐私语义

- 已核验一致：仓库生产代码不使用 `SavedStateHandle`；route 参数被限制为 StableId、封闭枚举、年月、正整数或校验后的 opaque key；test tag 是固定常量/稳定语义 ID，没有拼接金额或名称。
- 差异（并暴露契约内部冲突）
  - 原需求 13.7 明确禁止金额、账户/卡片/商户/参与人名称、经纬度等进入 `contentDescription`；但 13.2 的交易行示例又明确要求 TalkBack 朗读商户、账户和完整金额，两条规定无法同时满足。
  - 实际行为：实现选择了 13.2 的可读性路径：`AmountText` 把可见金额的完整金额文本写入 `contentDescription`，`JournalTransactionRow` 把包含账户/卡片等内容的 `accessibleText` 写入合并语义，地图也把业务 summary 写入 `contentDescription`。因此它符合 TalkBack 示例方向，却不符合 13.7 的逐字隐私禁令；只有“金额隐藏”状态会清除原值。

## 27. Compose 实现契约（契约第 15 章）

### 15.1 Theme API

一致。`LedgerColors`、`LedgerDimensions`、`LedgerMotion` 和 `LedgerTheme` 均为中央 API；feature 生产源码未发现颜色字面量、直接 MaterialTheme 或直接 Material Button/Card/TextField 使用。

### 15.2 组件 API 原则

- 已核验一致：业务组件普遍状态提升，UI model 使用 `@Immutable`，事件以用户意图命名，`Modifier` 不被用来取消内部 minimum size。
- 差异：契约禁止公共组件接受任意 `Color`，但 `LedgerCard` 公开 `containerColor: Color`/`borderColor: Color`，`LedgerIconView` 公开 `tint: Color`；API 本身允许调用方绕过封闭变体和中央语义色约束。

### 15.3 Screen API

- 已核验一致：feature 生产源码没有直接 import 另一 feature 的内部 Composable。
- 差异
  - 原需求：每个 feature 通过自己的 Routes 与 `EntryProviderScope.*Destinations()` 注册，并使用 core navigation 的公共 destination contract 跨 feature 导航。
  - 实际行为：没有 `EntryProviderScope` 或 feature route provider；`AppRootScreen`/`ReadyRootScaffold` 在 app 模块集中以 screen ID 字符串分发全部 feature destination，多个 feature action 也直接传 `onNavigate(String, Map<...>)`。路由契约虽为强类型生成，但 screen 入口层没有采用规定的 feature 注册 API。

### 15.4 UiState 和 UiAction

- 差异
  - 原需求：每个 screen 有单一 `UiState` 和封闭 `UiAction`，一次性导航/消息通过受控 effect。
  - 实际行为：app/feature 生产源码只找到 6 个名称为 `*UiState` 的 data class，找不到任何 `sealed ... Action`；主要模块使用覆盖整个 feature 的巨大 Content/FeatureState，加包含许多函数的 `*Actions` data class callback bag。多个页面还在 Composable 中维护 `remember` 草稿和 presentation override，未形成逐 screen 的单一状态/封闭事件契约。

### 15.5 文案和错误

- 已核验一致：错误主要映射为稳定 code 和资源文案，生产 UI 未发现展示 `exception.message`。
- 差异：没有统一 `UiText.Resource` 等价层；页面仍直接显示 `Enum.name`、内部 code/原始整数，并在 Composable 中格式化日期和金额，具体实例已在 JRN、BUD、LOA、ANA、IMP/RST 等页面章节记录。

### 15.6 列表和 Paging

- 已核验一致：流水使用 Paging、稳定交易 key、交易 content type 和 query-based `JournalSelectionSpec`，没有把 PagingData 转成完整 List 或持有 50 万 ID。
- 差异
  - 原需求：日期分组与大批金额格式化由 query/mapper 提供，滚动位置按稳定 key 恢复。
  - 实际行为：`JournalLazyColumn` 在组合期间对 `items.peek(index)` 全量循环生成日期头，并在每个交易 item 组合时新建 `LocaleCurrencyFormatter`、格式化金额；未提供显式 LazyListState/稳定 key 滚动恢复逻辑。

### 15.7 表单

一致。UI policy/reducer 处理草稿和格式预校验，实际 Journal/Posting/Effect 与不变量验证通过 application/domain port 提交；未发现 Composable 自行生成账务分录。

### 15.8 敏感状态

一致。生产代码不使用 `SavedStateHandle`；保险库使用一次性认证和 exposure registry，后台/锁定清除明文及剪贴板；附件图像缓存在锁定时清理；Preview 使用显式虚构 fixture，test tag 不含实际值。

### 15.9 MapLibre 包装

- 已核验一致：`:core:geo` 的 `LedgerMap` 统一管理 MapView 生命周期、样式、source/layer、聚类/热力图、token 色、attribution、替代表与释放；feature 不直接操作 MapLibre layer。
- 差异：wrapper 没有读取主题的 reduceMotion；聚类点击固定 `easeCamera`。因此没有完成契约所列的统一“主题和减少动画”职责（另见 `13.5`）。

### 15.10 Vico 包装

- 已核验一致：feature 只调用中央 `LedgerLineChart`/`LedgerColumnChart`/`LedgerStackedChart`/`LedgerPieChart` 并传类型化 model。
- 差异：包装没有统一颜色、marker、轴/网格样式、图例、空态或逐点 TalkBack；`ChartCard` 还重复执行两次 chart 插槽。详见 `8.25` 和第 26 节。

### 15.11 Glance

一致。小组件从 `WidgetSnapshotApplicationPort` 的 snapshot bundle 读取数据，使用受限 `LedgerGlanceTokens` 日/夜色和字号；配置 Activity 使用普通 Compose 设计系统。

### 15.12 Preview 和示例数据

- 已核验一致：统一 `PreviewFixtures` 是显式虚构数据；已有 7 档共享 Preview annotation，覆盖浅/深、320–600dp、最高 200% 及三语长文案。
- 差异：只有 14 个组合 Preview 场景，BatchSummary/BatchToolbar/BatchCommitBar、Dialog/BottomSheet/日期时间 picker 等大量公共组件没有各自的浅色、深色、200%、三语长文案及适用错误/禁用/选中 Preview；不满足“每个公共组件至少有”完整矩阵。

## 29. 完成定义（契约第 17 章）

- 差异：仓库不能按本契约标记为 UI 完成。虽然 215 个 screen ID、646 个 required state 名称、三语资源骨架、token、基线和静态门禁齐全，但本文件逐页记录了大量生产不可达状态、字段/操作缺失、滚动保存按钮、未本地化内部值、无障碍焦点缺口、图表包装缺陷及关键 UI 流程测试缺口；因此 DoD 第 2、3、4、5、7、9、10、11、13、14 项至少在部分页面不成立。

## 33. 最终冻结结论（契约第 21 章）

- 差异
  - 原需求：全应用只存在一套“静稳精确”中央设计系统，所有 feature 完整遵循冻结字段顺序、导航、语义、状态和高风险交互，未经版本评审不得改变。
  - 实际结论：中央 token、Theme、基础组件、导航参数防线和静态门禁已经建立，但页面/状态实现、图表系统、无障碍焦点、国际化细节、固定保存操作与测试闭环存在本报告所列差异。因此本项目当前 **不完全符合** 三份 UI 契约，不能把“215/646 名称覆盖”解释为 UI 合规完成。
