### 2026-09-02 — P37-04 bounded query contracts (first slice)

- Added dedicated application models for entry-core references, merchant/place suggestions, recent entry defaults, account summaries, and bounded account-history pages. Compatibility defaults keep existing fakes source-compatible while production overrides use dedicated access paths.

- Integrated separate bounded caches for entry core, suggestions, recent defaults, account summaries, and account history. Production lookups read the current book head before every hit, so a missed commit event cannot make an old revision valid; search keys retain only a SHA-256 fingerprint rather than typed names.
- Connected financial commit scopes to targeted invalidation, reference mutations to synchronous book invalidation, and lock/switch/restore/recovery/local-clear/ViewModel teardown to book/all-cache clearing.
- Added keyset cursor contracts and production implementations for category, merchant, place and location management pages plus single-account transaction/checkpoint/goal history. Each page uses `limit + 1`, a hard maximum, stable-ID tie breaking and a revision/generation-aware cache key.

- Replaced mutation-time fresh full snapshots and post-mutation full reloads with an authoritative account summary plus the currently visible bounded reference family; record state receives only revised account/card/totals.
- Replaced ordinary, refund, and specialized-entry full/wide reference reads with entry-core and bounded management/suggestion pages. The only remaining production `snapshot(FULL)` calls are explicit import-maintenance paths.

### 2026-09-02 — P37-05 route-first loading foundation

Same-key in-flight work is coalesced, changed keys supersede old publication, unchanged completed route content is reused, and failures keep prior content where it remains semantically usable.
